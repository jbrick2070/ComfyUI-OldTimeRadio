MUST-FIX BEFORE BUILD:
1. **[`_loudness_normalize_clip` – peak-safety gate logic]** "g=min(g, peak_ceiling/peak)" as stated will **not** apply the ceiling when the un-clamped gain `g` *plus* the peak would exceed the ceiling. Correct formula: `g = min(g, peak_ceiling / peak)`. However the prose says "`g=clamp(...); g=min(g, peak_ceiling/peak)`" which is correct *if* `peak` is the linear peak of the input clip. BUT the pseudo-signature says `peak_ceiling=0.95` and the legacy `target_peak=0.85`—in rms mode, the peak-safety step must compare the *computed* gain against `peak_ceiling / peak`, not some pre-clamped value named `peak_ceiling`. The doc is ambiguous whether `peak` means the scalar input peak or a parameter; the implementation must compute `input_peak = np.abs(clip).max()` and then set `g = min(g, peak_ceiling / input_peak)`. **Fix**: Clarify the variable scope in the function spec and ensure the implementation uses the actual input peak, not a parameter alias named `peak`.

2. **[`_level_dialogue_clip` – return type mismatch]** `_normalize_clip` returns `np.float32` (explicit `.astype(np.float32)`). The plan says `_loudness_normalize_clip` returns `(clip*g).astype(float32)`. But `_loudness_normalize_clip` computes RMS in float64 (`_rms(x) -> float64`) and the gain multiplication `clip*g` will upcast to float64 if any operand is float64, producing a float64 array before the `.astype(float32)` call. This is fine for the return value. However the early-exit paths ("empty/non-finite -> unchanged float32" and "peak<1e-6 -> unchanged") must return the *original* clip (which is already float32 from the resampler) or explicitly cast to float32; if they return a float64 silent array, downstream code (e.g., concatenation, crossfading) may fail or silently change dtype. **Fix**: Ensure all return paths in `_loudness_normalize_clip` and `_level_dialogue_clip` return `np.float32`. Specifically, the `return clip_np` fallthroughs must be `return clip_np.astype(np.float32)` if any prior op changed dtype, or guarantee `clip` stays float32.

3. **[`_master_loudness` – default when env unset + rms mode]** The plan says: "default it to 0.0 when `OTR_SEGMENT_LOUDNORM=='rms'` and the env is unset (transparent peak ceiling, no double-gain)." The plan states "explicit `OTR_MASTER_MAKEUP_DB` wins" which is correct. **Fix**: In `_master_loudness`, after the env-get, if the result is the default string `"4.0"` (or empty after strip), check the mode and use `0.0` for rms. The phrase "empty-string-safe parse" in the plan suggests a parse function handles this, but `_master_loudness` does not call it; the logic must be inline or the parse helper must be called. Verify: the plan says `_parse_env_float` is used for segment params, but `_master_loudness` still reads `os.environ.get("OTR_MASTER_MAKEUP_DB", "4.0")` directly. The plan's statement about "explicit `OTR_MASTER_MAKEUP_DB` wins" implies it will handle the rms default override.
