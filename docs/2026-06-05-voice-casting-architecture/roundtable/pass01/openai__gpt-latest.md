MUST-FIX BEFORE BUILD:
1. [Q1 / Model-agnostic registry] `_otr_voice_node_common.py:_OTR_CLONE_ENGINES` hard-codes `("indextts2", "chatterbox")` and `_render_per_line` branches on membership. A future clip-cloning engine with `voice_ref_field="voice_ref_path"` will not get ref resolution or Bark fallback; it will call `adapter.generate_voice(..., None, ...)` and likely hard-fail. This also violates the stated invariant “no per-engine ladders in generic dispatch.” Concrete fix: replace `_OTR_CLONE_ENGINES` with adapter/profile metadata, e.g. `requires_voice_ref=True`, `voice_ref_kind="wav_path"`, `missing_ref_fallback="bark"`, and have `_render_per_line` use that metadata instead of engine-name checks. Add this to the engine registration/profile schema and the “add engine” checklist.

2. [Q2 / Q5 / Kokoro stamped refs] `eng_kokoro.py:begin_episode` always picks a random legacy announcer voice from `ANNOUNCER_VOICE_POOL` and verifies that file before any per-line cast `voice_ref_id` is considered. `eng_kokoro.py:generate_voice` later gives `voice_ref` precedence, but it may never run if `begin_episode` picked a missing `bm_fable` / `bf_emma` / `bf_lily`. This is directly unsafe under the grounded state “kokoro 1/1 installed: announcer bm_george.” Concrete fix: make `begin_episode` only seed/store the fallback voice and move local-file verification to the actual `voice_id` used in `generate_voice`; or pass the resolved per-episode announcer `voice_ref_id` into `begin_episode` before preflight. The selected bank ref must suppress preflight of unrelated Kokoro voices.

3. [Q5 / preserve_ledger resolver] `_otr_voice_node_common.py:_resolve_clone_ref_path` re-derives a clone ref from `cast.get("gender")` at render time when `voice_ref_id` is absent. `cast_lock.py:_assert_unique_char_ids` validates only `char_id`; `cast_lock.py:_auto_registry` skips rows with missing gender but `preserve_ledger` does not validate/stamp gender at all. Therefore the render node has no shown guarantee that gender survives onto the cast row it reads. Concrete fix: do not rely on render-time re-casting for the default clone-engine path. When the selected character engine requires a reference clip, CastLock must either stamp canonical `voice_ref_id` for every character row before render or emit a structured “uncast/missing gender” report and intentionally mark that row for Bark fallback. Add a CastLock validator for required cast attributes used by casting: `char_id`, `gender`, optional `timbre`, `age_band`.

4. [Q7 / sample-rate contract] `_otr_voice_node_common.py:_render_per_line` only resamples Bark fallback clips. Primary adapter outputs are appended unchanged, while `sr` is overwritten from the engine profile and then passed to `pack_audio_batch`. If a future engine/profile pair drifts, or an adapter returns its actual file rate, the batch can still be mixed-rate. Concrete fix: after every `adapter.generate_voice` call, check `audio["sample_rate"]`; if it differs from the profile batch `sr`, either deterministically `resample_audio(audio, sr)` or fail at profile validation time with “adapter/profile sample_rate mismatch.” Do this for primary engine clips, not only Bark fallback.

5. [Q6 / commercial_clean routing] `cast_lock.py:_stamp` writes `entry["commercial_clean"] = ref.commercial_clean`, but `eng_indextts2.py:IndexTTS2Engine.commercial_clean = False` while the IndexTTS2 bank refs are `commercial_clean=true`. `_otr_voice_node_common.py:_render_per_line` builds the request with `commercial_clean=profile.commercial_clean`, not the cast-row value. A release gate that reads cast rows can incorrectly bless IndexTTS2 output because the reference clip is clean even though the model profile/adapter is non-clean. Concrete fix: define commercial cleanliness as a conjunction of engine/profile cleanliness and reference cleanliness. Stamp separate fields, e.g. `voice_ref_commercial_clean`, `engine_commercial_clean`, `commercial_clean_effective`, and make the release gate check the effective value. Also wire `assign_voice_for_slot(..., require_commercial_clean=True)` only when an explicit release/commercial gate is enabled.

6. [Q4 / default policy sequencing] `cast_lock.py:lock` defaults `cast_voice_policy="preserve_ledger"`, but `eng_indextts2.py` marks IndexTTS2 as the promoted default character engine and `_otr_voice_node_common.py` then best-effort resolves refs at render. This creates the observed mixed Index/Bark output despite refs being available. Concrete fix: do not globally flip the legacy-safe default blindly. Instead, make the voice node or CastLock select `auto_registry` automatically only when the chosen character engine declares `requires_voice_ref=True` and the ledger lacks `voice_ref_id`; keep `preserve_ledger` for Bark/legacy byte-identical paths. Document exactly that C7 byte identity is preserved only for Bark-selected legacy paths.
