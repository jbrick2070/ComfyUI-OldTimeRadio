VERDICT: yes-with-fixes. The problem is real, well-evidenced (live Opus trip), and the constraints are right. But the lever list is framed as a greenfield menu when the codebase ALREADY ships the load-bearing pattern, and it conflates two failure modes that need opposite treatments.

MUST-FIX BEFORE BUILD:
1. [Candidate levers A-F] The plan misses that the project ALREADY has the exact pattern the model-agnostic fix should extend. CONFIRMED in _otr_repair_prompts.py: there are six typed repair factories + a dispatcher (make_dispatching_repair_factory), incl. `cast_membership_repair`, which resolves its failure class DETERMINISTICALLY via the project's Levenshtein matcher (auto_remap_phantom, threshold 3) and hands `structured_call` a finished pydantic instance -- NO LLM repair call (CONFIRMED: structured_call's RepairPromptFactory may return a finished instance, returned with no LLM call). FIX: reframe levers A/E as "one more deterministic repair class": a field-key normalizer that snaps a model's keys to the schema's BEFORE the LLM repair, mirroring cast_membership_repair. This turns the headline fix from a new subsystem into an extension of a proven, tested seam, and it is inherently deterministic (constraint 3) and fail-loud-preserving (only benign key variance is mapped).

2. [Problem framing / lever B] The plan conflates TWO defects under "schema adherence" that need OPPOSITE fixes: (i) FIELD-NAME / shape variance -- the model used `index`/`lever`/`beat_index` where the schema wanted other keys (deterministically mappable); (ii) genuinely ABSENT semantic content -- the model omitted a value it was supposed to produce (NOT mappable). Lever B (relax required->optional with defaults) is actively dangerous for (ii): it would silently ship a defaulted-empty value instead of failing loud (violates constraint 4). FIX: split the design -- tolerant key-mapping for (i); keep fail-loud (or a LOUD deterministic fallback) for (ii). Never default a load-bearing field.

3. [Architecture assumption] The plan implicitly assumes all structured passes go through `structured_call`. CONFIRMED FALSE by the _otr_structured_call.py docstring: it shipped "MODULE + TESTS only," call-site migration deferred "Sprint 2B onward," and "each structured pass today hand-rolls its own call->parse->validate->repair." A model-agnostic guarantee that covers only the migrated passes is a FALSE guarantee -- an un-migrated hand-rolled pass will still hard-break on a different model. FIX: add a first-class step -- audit which passes are on `structured_call` vs hand-rolled; the hardening must cover each or explicitly exempt it, and that inventory drives the build order.

SHOULD-FIX:
1. [Lever C vs constraint 2] Schema-in-prompt up front changes the BASE prompt, which would change the LOCAL default model's output -> breaks byte-identity (constraint 2). Confine the schema hint to the REPAIR turn (lever D, where byte-identity does not apply), OR gate it so the local default prompt is byte-identical and only non-default models get the hint. Do not put it in every base prompt unconditionally.
2. [Missing piece -- measurement] No way to KNOW the fix is model-agnostic without burning GPU. Add a tiny offline conformance harness: a fixture set of real divergent model-output JSON shapes (the Opus `{index,lever,beat_index}` etc.) fed through the parse/repair layer, asserting each validates (or fails loud for the right reason). Model-agnostic verification, no live model needed -- and it pins the regression.

CUT THESE:
