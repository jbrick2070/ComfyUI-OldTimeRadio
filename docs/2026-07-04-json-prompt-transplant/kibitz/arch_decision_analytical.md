## VERDICT
**R** (in-repo JSON packs) -- the sibling+bridge+mirror shape is accidental complexity that does not earn its keep.

## production_mirror + bridge tax
`production_mirror/` is a permanent drift-maintenance liability, not a one-time cost. It's a hand-copied snapshot of OTR production files, pinned by SHA, that Phase A's own plan has to refresh EVERY time production moves (Chunk 0: re-copy files, recompute SHA256, rewrite the manifest baseline block, bump the pinned commit). The plan's own Chunk 5 comment -- "NEVER import the mirror... dependency-incomplete by design" -- concedes the mirror is a dead copy that can only be checked via AST-scraping, not executed. That's a synthetic staleness detector for a problem R doesn't have: if the JSON packs live in-repo, there is no second copy to go stale, no SHA to recompute, no manifest to hand-edit at every baseline bump. The bridge artifact adds a second real cost: it's an indirection layer (`get_pack_prompt_or_none` + registry + profile plumbing) that exists purely to ferry a string across a repo boundary that R would delete outright -- nodes would just `json.load()` the pack. Two real, recurring taxes; zero benefit visible in either doc that couldn't be had in-repo.

## ComfyUI packaging
A second registered custom-node pack (`ComfyUI-OTR-UpstreamStoryLab`) is a burden, not a benefit, for a single-operator, single-workflow repo. ComfyUI's node-pack model assumes packs are independently installable/updatable units for different users/graphs; here the sibling exists solely to feed one production repo's prompts. That's an install/version surface (two repos to keep in sync, two `git log` histories to reconcile against one workflow JSON) with no corresponding win -- nobody else consumes the sibling, and CLAUDE.md's own "one coder window," "workflow JSON is the single source of truth," and "no shims" rules all point at collapsing surfaces, not multiplying them.

## Reversibility now vs later
Now is cheap: Phase A is sibling-only, uncommitted, touches zero OTR production code or the workflow JSON (explicit in the scope statement). Redirecting today means retargeting 7 chunks to write JSON under `nodes/story_packs/` and skipping Chunk 0/5/6 (mirror refresh + AST byte-identity harness + anchor-doc rewrites) entirely -- less work, not more, since those three chunks exist only to serve the two-repo shape. After Phase B wires the bridge into production (new widgets, workflow JSON edits, routing code depending on the bridge's registry/profile API), reversing becomes a JSON-schema/config migration entangled with the workflow JSON -- exactly the class of change CLAUDE.md section 0 flags as highest-risk. Redirect now; the cost only grows.

## Best fit for the data-driven goal
The stated end-goal is "add a lane = drop a JSON file, zero routing code." A JSON pack sitting in `ComfyUI-OldTimeRadio/nodes/story_packs/` loaded directly by the existing node achieves that with one filesystem hop. T achieves the same content-owns-data property but wraps it in a cross-repo fetch + mirror-drift check that is pure ceremony relative to R.

## Confidence
**HIGH.** Grounded directly in the brief's own text (Chunk 0/5 mechanics, "never import the mirror," Phase A explicitly touches zero OTR production code) and CLAUDE.md's standing rules (workflow JSON as sole source of truth, one-repo-at-a-time coding discipline, root-cause-not-shim). No sibling-repo access was needed to reach this: the transplant plan itself supplies every fact needed to see the mirror/bridge as avoidable tax.
