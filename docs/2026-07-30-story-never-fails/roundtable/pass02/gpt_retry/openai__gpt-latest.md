VERDICT: build-ready as-is? no. Sections 3–6 leave critical exception classification, source-envelope selection, windowing, merge, and P3/P5 retry behavior either contradictory to current code or insufficiently specified.

MUST-FIX BEFORE BUILD:
1. [§4] The proposed outer campaign cannot catch `StructuredCallFailedError` “around `invoke_codex_structured`”: grounding shows that function converts it—and every other exception—into `CodexPassError`. This also makes candidate exhaustion indistinguishable from configuration/provider failures. Change the invocation boundary to preserve typed causes, e.g. raise a dedicated `CodexCandidateExhaustedError` only for `StructuredCallFailedError` and distinct permanent error types for configuration/runtime failures; have the campaign catch only the recoverable type. Do not classify failures by message text.

2. [§4, §5] P3 retry ownership contradicts the grounded lifecycle. The plan freezes accepted upstream passes and declares an “invalid accepted P3 graph/compiler state” non-retryable, while grounding says authored graph defects are recoverable and P3 is replayed when its graph is defective. Compile and fully validate the graph inside the P3 acceptance campaign. A typed authored-graph defect must reject that P3 candidate while preserving P0–P2; only a compiler invariant/configuration failure should exit permanently. P5 must never be asked to repair a defective P3 graph.

3. [§1, §3] The new envelope cannot be implemented from the shown `validate_payload_envelope(payload)` contract because the validator must distinguish registry-owned RSS from `operator_pinned`, but that source class is not among the described seven normalized fields. Define an explicit API such as `validate_payload_envelope(payload, *, source_policy)` with enumerated policies and exact limits. Apply the 2 MiB `full_text` byte check before serialization, the 2 MiB + 128 KiB normalized-payload check afterward, and retain 48,000 bytes for pinned premises. Specify the policy for linked-article and summary-selected bodies as well.

4. [§3.1] “Adapt `p0_source_chunks` to overlap” lacks an executable offset algorithm and is incompatible with the grounded implementation, which advances by `len(window)` and has no overlap. Define the invariant precisely: effective window content must exceed `MAX_QUOTE_CHARS - 1`; the next offset must be `previous_end - overlap`; sentence-boundary shortening must not produce zero/negative progress; the first offset is zero and the final end is `len(full_text)`. Reject invalid budgets rather than looping. Return explicit start/end metadata or define `end = offset + len(payload["full_text"])`.

5. [§3.1] The rebasing contract does not define how a span is identified as a `full_text` span or what constitutes its identity. [ASSUMPTION] The real span objects contain a source-field discriminator, but that shape is not shown. Verify the actual FactV4/EntityV4/NumberV4 span schema, then specify a typed rebaser that adjusts only spans whose source field is exactly `full_text`, including nested number evidence if present. Exact identity must include at least source field, rebased start, rebased end, and literal text; otherwise equal coordinates in different A0 fields can collapse incorrectly.

6. [§3.2] The merge is underdefined where overlapping windows produce duplicate facts with different bundle keys. It does not say which duplicate survives, whether numbers attached to a discarded duplicate can transfer to the survivor, or how number rows are ordered after fact selection. Define a single deterministic rule: stable traversal order, first surviving fact owns the canonical bundle, numbers from discarded bundles are either explicitly discarded or deterministically reparented after literal validation, then global number selection is capped and all parent IDs are mapped. Also define “nonempty window” separately for facts, entities, and numbers; FactIndexV4 already requires every accepted local result to contain at least one fact.

7. [§4, §5] P5 cleanup acceptance is ambiguous. The plan validates a P5 artifact, mutates it through cleanup, rescans it, and then refers to the “accepted artifact” without saying whether hashes and assembly use pre- or post-cleanup text. Make the cleaned artifact the sole returned P5 candidate, rerun schema, exact line-ID, spoken-surface, graph-reference, and safety validators after cleanup, and compute authorship/line hashes only from that final object. A residual authored-text finding rejects the entire candidate before `_assemble_ledger`.

8. [§4] Recoverability outside `invoke_codex_structured` has no typed interface. Missing/duplicate P5 rows, compiler defects, cleanup residuals, cancellation, and provider outages currently enter through different stages, yet the campaign instructions only describe catching `StructuredCallFailedError`. Define the campaign callable and result/error contract for each pass, including typed `CandidateRejected`, `Cancelled`, `ConfigurationError`, `ProviderUnavailable`, and deterministic invariant failures. Ensure cancellation is checked both between cycles and through the existing in-flight model-call cancellation/timeout seam; polling only before a blocking call is insufficient.

9. [§6] The Pro adapter is not implementable as specified. It gives no real dossier schema, caps, deduplication keys, window size/overlap rules, source-coordinate representation, or local validator signature. [ASSUMPTION] It is also unclear whether Pro dossier rows carry literal spans that can be validated against a window. Either remove complete-source Pro support from this build and limit scope to shared acquisition, or provide a separate spec grounded in `_otr_scifi_fable2.py`’s actual input/output models and validators.

10. [§2, §7] The provenance data model is incomplete. Define exact `meta.news_seed` keys and types, including route enum, nullable RSS index, raw alternative count, character count semantics, UTF-8 byte count, lowercase/uppercase SHA-256 encoding, and behavior for summary/article routes. Without this, exact receipt tests and backward-compatible serialization cannot be implemented consistently. Do not overload the existing `body_chars` without specifying whether it now means selected cleaned body characters.
