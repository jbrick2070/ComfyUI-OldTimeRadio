# Character-Voice "Whiny" Fix -- problem statement + roundtable judgment + hardened plan v1
*2026-06-10. Self-panel roundtable (Claude played all 4 panel seats AND the judge; $0 spend, every claim grounded against the live repo). Operator-corrected scope: the problem is WHINY character voices, NOT a vintage/modern aesthetic mismatch. PLANNING ONLY -- coder kickoff prompt at the end.*

## 1. Problem description (unchanged)
The character dialogue generated by the IndexTTS2 TTS model has an unintended "whiny" / pleading quality. The announcer voice (Kokoro) is fine in the mix; the primary character voices (Hayes, Gulliver) lack vocal weight and sound perpetually complaining. This degrades the audio and undercuts the scenes' dramatic tension. Era accuracy is NOT the issue -- modern-sounding delivery is acceptable.

## 2. Grounded reality check (what the code actually says)
Every item below was verified against the repo on 2026-06-10. The original draft's grounding section was partly STALE; this supersedes it.

- **G1 -- The bank is 37 indextts2 char refs, not 4.** `config/voice_reference_bank.json` holds 14 male + 22 female + LJSpeech/kathleen/kerstin narration refs for indextts2 (plus cb_*/dia_* mirrors of the same WAVs). The "only 1 CC0 female" claim in the first draft predates the donor expansion. Female additions are NOT needed.
- **G2 -- All 36 ref WAVs exist on disk** at `C:\ComfyUI-Models\TTS\refs\indextts2\`, so the missing-ref bark fallback SHOULD not fire. But note carefully: the fallback's WARNING goes only to the node's render_log STRING output, and `otr_runtime.log` carries ZERO voice-render lines (verified 2026-06-10 -- no "rendering N lines on", no engine names, nothing). **Per-line engine identity is not persisted anywhere, so bark rendering some or all character lines cannot be excluded retroactively.** See H4.
- **G3 -- Bank metadata is machine-stamped, never human-audited.** `scripts/otr_dl_indextts2_refs.py` tagged gender purely by median F0 (>=165 Hz = female) and stamped generic timbre (`donated,warm` for every male, `donated,bright` for every female). `vz_donor_james` and `vz_donor_hillbilly_jim` sit in the FEMALE pool -- probable threshold artifacts. Thin, near-threshold male donors (the exact "whiny" timbre) pass as male and enter the male casting pool unflagged.
- **G4 -- Casting for Hayes/Gulliver is a uniform per-episode lottery.** The canonical graph (`workflows/otr_scifi_16gb_full.json`) runs node 81 OTR_BatchCharacterVoices on **indextts2**, node 82 announcer on **kokoro**, and node 80 CastLock on **auto_registry** with `allow_voice_reuse=true` -- so CastLock stamps `voice_ref_id` per character (and its report STRING lists the casts, but that report is not persisted either). On the preserve_ledger default (fresh graphs), no ref is stamped and the render path resolves one at render time (`nodes/_otr_voice_node_common.py:_resolve_clone_ref_path`). Both routes go through `assign_voice_for_slot`. Inside the winning ladder tier the pick is `random.Random(seed).choice(pool)` -- **uniform**; the gender/timbre/role/age scores only sort the list, they do not weight the choice (`nodes/_otr_voice_bank.py:_pick`). Writer timbre vocab does not intersect the bank's `donated/warm/bright` tags, so the tier collapses to gender-only: every male character is a fair draw across all 14 male refs, including the weakest donor clips, re-rolled each episode_seed.
- **G5 -- scene_tension is never stamped.** Grep over `nodes/` shows `tension` only in the delivery module and its consumer; no writer emits it. So tension is always 0.0 and the delivery vector is **keywords + punctuation only** (`nodes/_otr_delivery_vector.py`).
- **G6 -- The derived vector is structurally biased toward whiny-adjacent emotions.** Interrogatives ("what", "who", "how", "wait", "look") cue `surprised`; "help/run/danger/hide/afraid" cue `afraid`; "sorry/lost/gone/alone" cue `sad`; "remember/once/ago/silence/empty/distant" cue `melancholic` -- all high-frequency words in a SIGNAL LOST script. Each "?" adds 0.5 raw to surprised; 3 cues saturate a dim at 1.0 (`_CAP=3.0`); there is **no cap on total emotion mass** (sum can exceed 4.0); `calm = max(0, 1 - 0.5*raw_arousal)` collapses to 0 with ~2 raw arousal points. Net: ordinary dramatic lines ship near-saturated afraid/sad/surprised mixtures.
- **G7 -- emo_alpha is pinned at 1.0.** `nodes/_otr_audio_engines/eng_indextts2.py:generate_voice` hardcodes `"emo_alpha": 1.0`; the worker (`scripts/_otr_indextts2_worker.py`) already accepts a per-request value, so exposing it is adapter-side only. Full-strength multi-hot emotion vectors are exactly the regime where IndexTTS2 prosody goes exaggerated/pleading.
- **G8 -- A true-neutral A/B already exists for free.** `OTR_DELIVERY_VECTOR=0` makes the vector None -> all-zero -> the worker omits `emo_vector` entirely (pure clone of the ref). Note: a "neutral" line under the default path still sends `calm=1.0` at alpha 1.0, which is NOT the same render as no-vector -- whether IndexTTS2 treats them identically is unverified.
- **G9 -- Observability gap (the real diagnosis blocker).** On the default preserve_ledger path the resolved `voice_ref_id` per character is never logged and never restamped to the ledger. The operator cannot tell from any artifact WHICH donor ref produced a whiny Hayes. (auto_registry logs casts in the CastLock report; the default path logs nothing.)
- **G10 -- Versioning hooks for every proposed change already exist.** `DELIVERY_TABLE_VERSION="v1"` (bump to v2 on retune); bank identity is `voice_bank_id+sha` (bank edits are a designed re-baseline trigger); delivery profiles are identity-only scaffolding ("populated profiles arrive in v2.1") and are NOT applied in the per-line path today.
- **G11 -- Same-voice collision is possible.** Render-time resolution calls `assign_voice_for_slot(..., allow_voice_reuse=True)` per character with no episode used-set, so two male characters can draw the same ref in one episode (per-char seeds usually differ, but nothing forbids a collision). Distinct bug, same neighborhood.

## 3. Root-cause hypotheses (refined)
- **H1 Timbre (ref pool):** thin/nasal donor refs in the uniform male lottery. Mechanism grounded (G3+G4). Likelihood: high, episode-dependent (re-rolls each seed -- which also explains "some episodes sound worse").
- **H2 Delivery (vector + alpha):** keyword-saturated afraid/sad/surprised vectors at emo_alpha 1.0. Mechanism grounded (G6+G7). Likelihood: high, affects ALL characters on emotional lines regardless of ref.
- **H3 Both, compounding:** a thin ref + a saturated afraid vector is the worst case. The fix plan addresses both cheaply; P0 tells us the mix.
- **H4 The whiny lines might literally BE bark (operator-ear evidence, 2026-06-10).** The operator reports the indextts2-era character voices sound like the OLD bad bark renders. The engine widget says indextts2 and a missing worker fails closed, but the per-line bark fallback is warning-only-to-STRING and nothing persists per-line engine identity (G2/G9) -- so for already-rendered episodes H4 is OPEN, not ruled out. P0-zero settles it for a fresh render in minutes; P3a makes it impossible to wonder ever again.
- Ruled out: era/vintage mismatch (operator), announcer path (Kokoro untouched), engine-widget misconfiguration (verified indextts2 in the canonical graph).

## 5. Hardened plan v1 (no architectural overhaul; all changes additive + versioned)
**P0-zero -- PROVE which engine rendered (first action, ~10 min, zero code).** Queue one 30-word smoke episode (`scripts/queue_smoke.py` + `otr_api.py`), then read node 81's `render_log` and node 80's CastLock report out of `/history/<prompt_id>`. The dispatch prints `char_voice: rendering N lines on 'indextts2' (profile ...)` and, if any line fell back, `WARNING ... rendering those on 'bark'`; the CastLock report names every char -> voice_ref_id. Outcomes: (a) all-indextts2 -> H4 closed, whiny is genuinely indextts2, proceed P0; (b) bark warnings present -> the whiny sound IS bark, fix the ref resolution break FIRST and re-listen before any calibration.
**P0 -- Diagnose timbre vs delivery (operator GPU, ~30 min, zero code).** Drive the Path-B worker directly (spawn `index-tts\.venv` python on `scripts/_otr_indextts2_worker.py`, send hand-built JSON requests). One fixed dramatic line, one fixed seed, matrix:
  A. ref=`vz_bill_boerst` (warm/baritone), emo_vector omitted
  B. ref=`vz_bill_boerst`, derived vector at alpha 1.0 (reproduce current path)
  C. ref=worst-suspect donor (pick 2-3: highest-F0 males from the audit table, P2a can run first on CPU), emo omitted
  D. ref=`vz_bill_boerst`, calm=1.0 vector at alpha 1.0 (settles G8's open question)
  E. ref=`vz_bill_boerst`, derived vector at alpha 0.65
  Listen. B-vs-A isolates delivery; C-vs-A isolates timbre; E sizes the cheap alpha win. Decision gate: which of P1/P2 is primary (likely both).
**P1 -- Delivery calibration (coder, CPU-green, one session).**
  1. Delivery table v2 in `nodes/_otr_delivery_vector.py`: cap total non-calm mass (normalize sum to <=1.2), floor calm at 0.15 when any speech is unexcited, demote stop-word-frequency cues (drop or half-weight "what/who/how/look/wait"), fix punctuation double-dip. Bump `DELIVERY_TABLE_VERSION` to "v2". Property tests: random corpora -> mass cap holds, calm floor holds, pure-neutral text -> calm-dominant.
  2. Expose `OTR_INDEXTTS2_EMO_ALPHA` (float env, default **0.65**, clamp 0..1) in `eng_indextts2.generate_voice`; worker already honors it -- zero worker change. `OTR_DELIVERY_VECTOR=0` stays the escape hatch.
**P2 -- Bank audit + curation (tooling: coder; listening: operator ~20 min).**
  a. Add `--audit` mode to `scripts/otr_dl_indextts2_refs.py` (reuse its pyin machinery): per ref -> duration, median F0, voiced fraction, clipping/SNR proxy, ranked thin-risk list (high-F0 males first), flag the 2 suspect female tags. CPU-only, runs today.
  b. Operator listen pass over the ranked list -> stamp additive optional fields `quality_tier` ("a"/"b"/"reject") and corrected `gender` in the bank (schema permits extra keys; add them to `voice_bank_entry_schema.json` as optional).
  c. Caster honors tiers by FILTERING (tier-a pool first, tier-b fallback, never "reject") -- do NOT reweight `_pick`; filtering is the minimal, ladder-shaped change. Mislabels corrected. Net effect: the lottery only contains voices that passed a human ear.
  d. Config-only quality win (operator, zero code): the canonical graph sets CastLock `allow_voice_reuse=true` (a relic of the 3-male-ref era). With 14 male refs, set it false so two characters can never share a voice in one episode.
**P3 -- Observability + collision (coder, small, same session as P1).**
  a. LOUD per-LINE persistence of `engine` + resolved `voice_ref_id` (and any fallback swap): log line + ledger restamp on BOTH casting routes (same convention as the fallback restamp directive: log the swap, stamp the ledger, never silent). PRIORITY RAISED by H4 -- after this ships, "was that bark?" is answerable from the saved ledger of every episode, forever.
  b. Per-episode used-set in `_resolve_clone_ref_path` so two characters cannot share a ref while unused same-gender refs remain (G11).
**P4 -- Verify (gates, in order).** Full suite + Bug Bible regression (must stay green); confirm `test_audio_byte_identical` is bark-path and unaffected; one 30-word GPU smoke via `scripts/queue_smoke.py`; then one full episode re-render and an operator listen-QA -- the DONE bar is "Hayes/Gulliver no longer read as whiny on a fresh episode," operator-judged.
