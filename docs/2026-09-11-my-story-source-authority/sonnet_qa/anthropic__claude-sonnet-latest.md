Findings:

**1. `endpoint` unused in production when `global_ending` empty but treatment.ending has whitespace-only content — masking check inconsistency.** `global_ending = treatment.ending if is_last and treatment.ending.strip() else ""`; `endpoint = global_ending or plan.ending_state`. Fine, but note the test explicitly exercises `ending=" \n\t"` and `""` distinctly as separate parametrize cases yet both collapse to identical code path (`global_ending=""`) — redundant test case, not a defect but wasted coverage (over-engineering in test matrix: 4×5×2=40 combos, many degenerate).

**2. Structural duplication between `_pass_act`'s three near-identical `act_scope` string blocks.** All three branches repeat "Earlier events need not be repeated"/final-act boilerplate with small variations, authored inline rather than templated. Not fatal, but a copy-paste defect risk: any future wording fix must be applied in two places (final-with-global vs final-without-global) that share ~80% text. A future edit could easily update one and miss the other, silently reintroducing incoherence between P0/P1 — exactly the kind of drift this fix intends to close permanently.

**3. `_pass_act` mutates `source_kwargs` dict in-place with `source_kwargs["source_rewrite_instruction"] = act_scope`** then splats `**source_kwargs` into `_call`. If caller ever passes `source_rewrite_instruction` explicitly too (not currently possible per API, but no guard), this silently overwrites it with no error — silent clobbering rather than a defensive `assert` or explicit param. Minor robustness gap, but the diff introduces a new implicit contract (source_kwargs must not already contain the key) that isn't enforced or tested directly (tests only assert absence downstream at `structured_call`, not that `_pass_act` raises if misused).

**4. Test `test_act_endpoint_and_scope_reach_both_owners_independent_of_unheard_cast` asserts `"GLOBAL" not in scope` as a proxy for "model-derived ending is data, not system text."** This is a weak substring check — it only catches the literal word "GLOBAL" appearing in fixture data, not a general guarantee that ending text never leaks into `act_scope`. Since `act_scope` is built from fixed string literals only (no interpolation of `treatment.ending`), this assertion is trivially true by construction and doesn't actually test anything meaningful; it's decorative coverage, not a real regression guard. Mislabeling this as verifying "no ending leaks into system text" overstates what's tested.

**5. Fourth ending parametrize case is adversarial-string-in-data test:** `ending="  GLOBAL 100%\nACT SCOPE: quoted story text\n- where it should leave the story: END  "`. This is designed to catch injection-style false-positive matches in the test's own parsing logic (e.g. `rsplit("\nACT SCOPE: ", 1)` could break if ending itself contains "ACT SCOPE:"). But note: this ending string only appears when `is_last and ending.strip()`, i.e. `expected = ending` — the test's own `target_area.endswith(...)` check with this exact string containing `\n- where it should leave...` embedded inside is somewhat self-referential and hard to reason about; risk of the test itself passing for the wrong reason (asserting on data containing look-alike delimiters used by the test's own string-splitting), which is fragile: any minor format change to system prompt separators could make this pass/fail non-deterministically depending on where `rsplit`/`split` cut, not because production is correct.

**6. Scope leak test (`test_act_scope_does_not_leak_to_other_phases_of_the_real_runner`) hardcodes `len(corrections) == 9` and `len(slots.calls) == 18`** for a 6-act run — brittle magic numbers coupling test to exact internal call-count arithmetic (6 acts + interstitials + frame etc.). Any future addition of a new pass (e.g. new correction step) breaks this test without necessarily indicating an actual regression in scope leakage — the assertion conflates "total call count is what I expect" with "scope did not leak," two different concerns bundled into one brittle number.

**7. Bug Bible entry says "tests prove routing and application, not a live model's semantic fidelity"** — appropriately honest, but the entry doesn't document the *actual* prior failure mode's root cause (i.e., that the previous act-writer prompt only carried `plan.ending_state`, never `treatment.ending`, for the final act) as a concrete before/after diff reference. Future readers of BUG_BIBLE.yaml get prose but no pointer to the exact old code line that caused canonical06, weakening the bible's traceability value emphasized elsewhere in the process.

**8. R4 judgment table addresses "multiline ending malformed list" by asserting free-text transport is fine,** but the QA diff's adversarial ending-string test (item 5 above) is the *only* place this claim gets exercised, and as noted it's testing the test harness's parsing robustness more than production behavior — so the "no malformed-list" risk is not actually closed by concrete production-code assertions (e.g., no test confirms the literal act_scope text survives untouched when ending contains embedded newlines matching the prompt's own section markers, only that the *outer* wrapper test's string-splitting still functions).

**9. Minor: `_pass_frame` and other `_call` sites now receive `source_rewrite_instruction=""` default silently** — frame/treatment/interpret calls get no act-scope instruction at all (correct per design), but there is no explicit test confirming `rewrite_story_source`'s `instruction=""` for frame/treatment stays empty (i.e., that scope truly never reaches those owners) beyond the one runner-level leak test's `else` branch, which only checks the correction system-prompt text, not the `_call` kwarg itself. Coverage gap between unit-level and integration-level scope-isolation claims.

Overall: the change is reasonably scoped and honest about its limits, but has (a) real duplication/maintainability risk in the three `act_scope` string blocks, (b) at least one decorative/non-diagnostic test assertion (`"GLOBAL" not in scope`), (c) a fragile magic-number leak test, and (d) a self-referential adversarial-string test whose passing doesn't clearly validate production correctness.
