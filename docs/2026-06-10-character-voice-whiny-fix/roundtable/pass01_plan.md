*2026-06-10. Two review rounds: (1) self-panel (Claude, $0); (2) LIVE 4-model OpenRouter pass -- GPT-5.5, Gemini 3.1 Pro, Grok 4.3, DeepSeek V4 Pro -- open-ended prompt, every surviving claim grounded against the repo. ## 1. Problem description (unchanged)
The character dialogue generated by the IndexTTS2 TTS model has an unintended "whiny" / pleading quality. The announcer voice (Kokoro) is fine in the mix; the primary character voices (Hayes, Gulliver) lack vocal weight and sound perpetually complaining. This degrades the audio and undercuts the scenes' dramatic tension. Era accuracy is NOT the issue -- modern-sounding delivery is acceptable.

## 2. Grounded reality check (verified against the repo 2026-06-10)
- **G1 -- The bank is 37 indextts2 char refs, not 4.** 14 male + 22 female + narration refs (plus cb_*/dia_* mirrors). The "only 1 CC0 female" claim in the first draft was stale; female additions are NOT needed.
- **G2 -- All 36 ref WAVs exist on disk** at `C:\ComfyUI-Models\TTS\refs\indextts2\`, so the missing-ref bark fallback SHOULD not fire. But the fallback's WARNING goes only to the node's render_log STRING output, and `otr_runtime.log` carries ZERO voice-render lines. **Per-line engine identity is not persisted anywhere, so bark rendering some or all character lines cannot be excluded retroactively.** See H4.
- **G3 -- Bank metadata is machine-stamped, never human-audited.** `scripts/otr_dl_indextts2_refs.py` tagged gender purely by median F0 (>=165 Hz = female) and stamped generic timbre (`donated,warm` / `donated,bright`). `vz_donor_james` and `vz_donor_hillbilly_jim` sit in the FEMALE pool -- probable threshold artifacts. Thin near-threshold males pass as male unflagged.
- **G4 -- Casting is a uniform per-episode lottery.** Canonical graph (`workflows/otr_scifi_16gb_full.json`): node 81 char voices on **indextts2**, node 82 announcer on **kokoro**, node 80 CastLock on **auto_registry** with `allow_voice_reuse=true`. Inside the winning ladder tier the pick is `random.Random(seed).choice(pool)` -- **uniform; scores only sort, they never weight** (`nodes/_otr_voice_bank.py:_pick`). Writer timbre vocab does not intersect bank tags, so the tier collapses to gender-only across all 14 male refs, re-rolled each episode_seed.
- **G5 -- scene_tension is never stamped.** No writer emits it; tension is always 0.0; the delivery vector is **keywords + punctuation only** (`nodes/_otr_delivery_vector.py`).
- **G6 -- The derived vector is structurally biased toward whiny-adjacent emotions.** Interrogatives ("what","who","how","wait","look") cue `surprised`; "help/run/danger/hide/afraid" cue `afraid`; "sorry/lost/gone/alone" cue `sad`; "remember/once/ago/silence/empty/distant" cue `melancholic`. Each "?" adds 0.5 raw to surprised; 3 cues saturate a dim (`_CAP=3.0`); **no cap on total emotion mass**; `calm = max(0, 1 - 0.5*raw_arousal)` collapses fast. A line with both "what" and "?" double-dips the same emotion.
- **G7 -- emo_alpha is pinned at 1.0** (`eng_indextts2.py:generate_voice`); the worker already accepts a per-request value, so exposing it is adapter-side only.
- **G8 -- A true-neutral A/B exists for free.** `OTR_DELIVERY_VECTOR=0` -> vector None -> all-zero -> the worker omits `emo_vector` entirely. Note: a "neutral" line under the default path still sends `calm=1.0` at alpha 1.0 -- NOT the same render as no-vector; IndexTTS2's calm semantics are UNVERIFIED (calm may be an active suppression mode, not "rest").
- **G9 -- Observability gap (the diagnosis blocker).** Default-path resolved `voice_ref_id` per character is never logged or persisted; CastLock's auto_registry report STRING lists casts but is not persisted either.
- **G10 -- Versioning hooks exist for every proposed change.** `DELIVERY_TABLE_VERSION="v1"`; bank identity = `voice_bank_id+sha`; delivery profiles are dormant identity-only scaffolding.
- **G11 -- Same-voice collision is possible.** The render-time path resolves per character with `allow_voice_reuse=True` and no episode used-set. (CastLock's auto_registry DOES keep a `used` set -- the widget `allow_voice_reuse=true` is what defeats it on the canonical graph.)
- **G12 -- (pass 1) The IndexTTS2 adapter skips the full text normalization.** `IndexTTS2Engine.prepare_text` calls only `clean_spoken_text` -- NOT the module-level `prepare_text` that collapses dot-runs and strips asterisks/music glyphs. `?`, `!`, `...` ride into the engine, which reads punctuation prosody **independently of the emotion vector**: a script full of "What?!" can plead even with the vector off.
- **G13 -- (pass 1) The delivery vector is derived from RAW pre-strip text** (`_otr_voice_node_common.py:407-410` runs before `prep(text)` at :414). Parenthetical stage directions can cue emotions and then vanish from the spoken text.
- **G14 -- (pass 1) Ref preprocessing is peak-normalized, not loudness-normalized, and rate-mismatched.** `otr_dl_indextts2_refs.py` writes every ref at 44100 Hz PCM_16, normalized to peak 0.97 (`span / peak * 0.97` -- verified at 3 call sites). No LUFS/RMS match, no clipping/SNR screen (`classify_and_trim` returns only gender/F0/voiced/trim). The engine is 22050 Hz; whether IndexTTS2 resamples the prompt cleanly is UNVERIFIED.
- **G15 -- (pass 1) Solo-vs-mix is unsplit.** Kokoro emits dense, compressed, radio-ready audio; IndexTTS2 zero-shot output is dynamic and may lack low-mid body. Nothing measures character-clip loudness/spectrum against the announcer or the music bed, so "whiny" may be partly a MIX-perception artifact.
- **G16 -- (pass 1) Reuse/tier integration constraints verified.** `assign_voice_for_slot` raises `VoiceCastingError` on exhaustion when reuse is off, but CastLock's char branch CATCHES it ("NOT cast" -> continue -> render-time resolution takes over). So flipping `allow_voice_reuse=false` degrades gracefully, never crashes. `assign_voice_for_slot` has no tier concept -- tier filtering must pre-filter the bank pool, preserving the ladder.

## 3. Root-cause hypotheses (v2 -- now four channels, all mechanism-grounded)
- **H1 Timbre/read-style (ref pool):** thin, noisy, or politely-read donor refs in the uniform male lottery. A zero-shot cloner copies READ STYLE (up-talk, breathiness, hesitancy) as aggressively as timbre -- F0 alone cannot rank this (unanimous panel finding).
- **H2 Delivery (vector + alpha):** keyword-saturated afraid/sad/surprised vectors at emo_alpha 1.0.
- **H2b Punctuation prosody (NEW, pass 1):** `?`/`!`/`...` reach the engine un-normalized (G12) and shape pitch contours independently of H2. A "?"-heavy script pleads even with the vector off.
- **H2c Mix perception (NEW, pass 1):** character clips may be quieter/thinner than the Kokoro announcer against the music bed (G15) -- a post/mix channel, not a TTS channel.
- **H3 Compounding:** worst case = thin ref + saturated vector + rising "?" contour + under-weighted clip in the mix. P0 isolates each channel.
- **H4 The whiny lines might literally BE bark (operator-ear evidence).** Engine widget says indextts2 and a missing worker fails closed, but the per-line bark fallback is warning-only-to-STRING and nothing persists per-line engine identity (G2/G9) -- OPEN for already-rendered episodes; P0-zero settles it for a fresh render.
- Ruled out: era/vintage mismatch (operator), announcer path, engine-widget misconfiguration (verified indextts2 in the canonical graph).

## 5. Hardened plan v2 (no architectural overhaul; all changes additive + versioned)
**P0-zero -- PROVE which engine rendered (first action, ~10 min, zero code).** Queue one 30-word smoke (`scripts/queue_smoke.py`), read node 81 `render_log` + node 80 CastLock report from `/history/<prompt_id>`. Look for `rendering N lines on 'indextts2'` vs `WARNING ... rendering those on 'bark'`. (a) all-indextts2 -> H4 closed for fresh renders, proceed; (b) bark warnings -> fix ref resolution FIRST, re-listen before any calibration. Limitation stays explicit: proves fresh renders only; past episodes are unknowable until P3a ships.
**P0 -- Audition matrix (operator GPU, ~45 min scripted, zero pipeline code).** Drive the Path-B worker directly with hand JSON. **3 lines** (neutral declarative / question-heavy / fear-urgent) x **3 seeds**, loudness-matched playback. Conditions per line:
  1. best-guess ref (`vz_bill_boerst`), vector OMITTED  (clean baseline)
  2. same, derived v1 vector @ alpha 1.0               (reproduce today)
  3. same, alpha sweep 0.25 / 0.45 / 0.65               (pick the default empirically -- do NOT assume 0.65)
  4. same, calm=1.0 only @ alpha 1.0                    (calm semantics, G8)
  5. same, angry floor 0.15, rest zero                  (Gemini "project from the chest" cell)
  6. same, punctuation-softened text (? -> .), vector OMITTED  (isolates H2b)
  7. worst-suspect ref (top of P2a thin-risk list), vector OMITTED   (isolates H1)
  8. worst-suspect ref @ alpha 0.65                     (H3 interaction cell)
  9. one ref pre-resampled to 22050 mono, vector OMITTED (G14 rate check)
  Decision gate: per-channel verdicts for H1/H2/H2b + chosen alpha default + calm handling + whether the punctuation lever earns a place in P1.
**P1 -- Delivery + text calibration (coder, CPU-green, one session; defaults set by P0 data).**
  1. Delivery table v2 (`nodes/_otr_delivery_vector.py`), version bump to "v2": derive from the PREPARED/cleaned text not raw (G13); demote stop-word interrogative cues; count punctuation once (no keyword+punct double-dip); Grok "de-bleat" rule (terminal-? + afraid/sad cue -> demote surprised); total-mass control with the STRATEGY chosen from P0 (candidates: normalize-sum, primary-keeps-full + cap-secondaries, soft penalty above the cap) -- no unconditional calm floor (3 of 4 panelists: risky before P0 cell 4 data). Optional short-line dampening (DeepSeek) only if P0 shows one-word exclamations saturating. Property tests: pure-neutral text -> calm-dominant (>=0.7); mass cap holds on random corpora; "?"-only line never saturates surprised.
  2. Expose `OTR_INDEXTTS2_EMO_ALPHA` (float env, clamp 0..1, default = P0 winner); worker already honors it. This knob alone is the cheapest dominant step and ships even if the table retune waits.
  3. Punctuation lever, experiment-gated: `OTR_CHAR_DECLARATIVE_Q=1` (default OFF) -- terminal `?` -> `.` for character lines only (announcer untouched), applied AFTER vector derivation so the vector still sees the question. Promote to default only on listen evidence. Also fix G12: adapter prepare_text adopts the full shared normalization (dot-run collapse etc.) as a versioned change.
**P2 -- Bank audit + curation (tooling: coder; listening: operator).**
  a. `--audit` mode in `scripts/otr_dl_indextts2_refs.py`: per ref -> duration, sample rate, median F0 + std, voiced fraction, RMS/LUFS proxy, crest factor, clipping count, spectral centroid, **chest-weight (80-300 Hz energy / total RMS)**, nasal-band ratio (~800-1500 vs 150-350 Hz), end-of-line F0 rise; composite thin-risk ranking (NOT F0-only -- unanimous panel); flag gender-ambiguous refs (F0 145-185 Hz) as must-listen; flag the 2 suspect female tags. CPU, runs today.
  b. **Audition reel** for the listen pass (GPT): auto-render per candidate ref a fixed 6-line panel (neutral / command / question / fear / grief / exposition), vector-off + calibrated, loudness-matched -> operator grades a reel, not raw donor WAVs (tests the CLONER, not the source). Stamp additive optional fields: `quality_tier` ("a"/"b"/"reject"), corrected `gender`, optional `style_tags` (e.g. `lead_safe`, `nasal_risk`).
  c. Caster honors tiers by PRE-FILTERING the pool before the ladder (G16: `assign_voice_for_slot` has no tier concept; filter, never reweight `_pick`): leads/recurring chars draw tier-a (`lead_safe` preferred), minor roles may draw tier-b, "reject" never. Accept the variety-collapse tradeoff explicitly (few tier-a males beats whiny leads).
  d. Config win, re-scoped after G16: on the canonical graph flip CastLock `allow_voice_reuse` -> false. CastLock's own used-set then enforces uniqueness; over-pool characters degrade gracefully to render-time resolution (no crash -- verified). The preserve_ledger path still needs P3b.
**P3 -- Observability + collision (coder, small, same session as P1).**
  a. Per-line `engine` + resolved `voice_ref_id` + `emo_alpha` + delivery version persistence. Design per pass-1 finding: node-local ledger mutation does NOT persist by itself -- emit in render_log ALWAYS (char -> ref -> engine map + per-fallback line), mirror to the runtime log, and restamp the durable episode ledger via the same route the video lane uses for fallback restamps; additive fields only (never touch hash-sensitive keys). PRIORITY: blocks P2c sign-off -- without it no curation claim is testable. After this, "was that bark?" is answerable forever.
  b. Per-episode used-set in `_resolve_clone_ref_path` with a **per-character resolve-once cache** (resolve each char_id once, reuse for all its lines, then mark used -- a naive per-line used-set would re-voice a character mid-episode; GPT pass-1 catch). Prefer-unique, reuse-only-on-exhaustion semantics.
**P4 -- Verify (gates, in order).** Full suite + Bug Bible regression green; confirm `test_audio_byte_identical` is bark-path and unaffected; 30-word GPU smoke (`scripts/queue_smoke.py`); full episode re-render; **solo-vs-mix gate (NEW)**: audition suspect character lines solo loudness-matched, THEN in the full mix -- solo-OK/mix-thin routes to a separate post/mix decision (H2c: e.g. RMS-match character clips toward the announcer's integrated loudness as a versioned, default-off option), solo-whiny routes back to P1/P2. DONE bar unchanged: Hayes/Gulliver no longer read as whiny on a fresh episode, operator-judged.
