## Change 2 -- BUG-LOCAL-004: KV-cache flush + parse-retry cap

In the same `write_script` method, the short-episode branch (`target_words <= 700`)
got two additions before the main `_generate_with_llm` call:

```python
# Flush VRAM before main script gen
try:
    _flush_vram_keep_llm()
    _runtime_log("ScriptWriter: VRAM flushed before main generation (BUG-LOCAL-004)")
except Exception as _flush_err:
    log.debug("[LLMScriptWriter] _flush_vram_keep_llm pre-main-gen failed: %s", _flush_err)

# Parse-retry cap with cheap structural-marker check
MAX_PARSE_RETRIES = 2
_parse_attempt = 0
script_text = ""
while _parse_attempt < MAX_PARSE_RETRIES:
    _parse_attempt += 1
    _runtime_log(
        f"ScriptWriter: GENERATE attempt={_parse_attempt}/{MAX_PARSE_RETRIES} "
        f"max_new_tokens={max_new_tokens} target_words={target_words}"
    )
    script_text = _generate_with_llm(
        full_prompt, model_id=model_id, max_new_tokens=max_new_tokens,
        temperature=temperature, top_p=active_top_p,
        optimization_profile=optimization_profile, live_ledger=True,
    )
    _voice_hits = len(re.findall(
        r'^\s*\[VOICE:\s*[A-Z_]+', script_text or "", re.MULTILINE
    ))
    _bare_hits = len(re.findall(
        r'^[A-Z][A-Z0-9_ ]{1,19}:\s*\S', script_text or "", re.MULTILINE
    ))
    if _voice_hits + _bare_hits > 0:
        _runtime_log(
            f"ScriptWriter: PARSE_OK attempt={_parse_attempt} "
            f"voice_hits={_voice_hits} bare_hits={_bare_hits}"
        )
        break
    _runtime_log(
        f"ScriptWriter: PARSE_FAIL attempt={_parse_attempt} ..."
    )
    if _parse_attempt < MAX_PARSE_RETRIES:
        try:
            _flush_vram_keep_llm()
        except Exception:
            pass
```

`_flush_vram_keep_llm()` is a 14-line helper that calls `gc.collect()` and
`torch.cuda.empty_cache()` if CUDA is available. It does NOT unload the LLM weights.

Question 2A: the OOM at 26.53 GiB on a 16 GB device suggests cumulative KV cache
or transient activation peaks that aren't released by `empty_cache()` alone.
Is `empty_cache()` enough here, or should we also explicitly delete the model's
internal `past_key_values`/`DynamicCache` between calls? The model is held in
`_LLM_CACHE` between calls.

Question 2B: the parse check is permissive -- one match of either `[VOICE: NAME]` OR
bare `CHARACTER:` form passes. The 30-word smoke prompt explicitly forbids the bare form.
Is the permissive check appropriate (other code paths use bare form), or should the
ultra-smoke branch use a strict-VOICE-only check to avoid false-pass on a degenerate
output that has one accidental `CHARACTER:` line?

Question 2C: MAX_PARSE_RETRIES = 2 means at most 2 forward passes. With 4-bit NF4 weights
~7.5 GB resident plus 16384-context KV cache ~6 GB BF16, two passes should fit. Is 2 the
right cap, or does this need to be parametric on `target_words`?
