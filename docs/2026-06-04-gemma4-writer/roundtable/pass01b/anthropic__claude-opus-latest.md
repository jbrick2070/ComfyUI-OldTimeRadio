1. ["The blocker (grounded)" + `generate()` in _otr_openrouter_backend.py] The plan asserts the failure is purely "instruction-compliance" / over-generation. The grounding shows a concrete mechanical cause the plan ignores: the inventor calls `generate_fn(..., max_new_tokens=_INVENTOR_MAX_TOKENS)` with `_INVENTOR_MAX_TOKENS = 80`, but `OpenRouterBackend.generate` does `out_tokens = max(int(max_new_tokens or 0), floor)` where `floor = DEFAULT_MIN_OUTPUT_TOKENS = 1024`. So on the Ollama lane the inventor's 80-token cap is silently raised to **1024**, which is what lets gemma emit 63 lines. The local transformers path would honor 80 and truncate. Fix: before/alongside B, set `OPENROUTER_MIN_OUTPUT_TOKENS` (env, per the code) low for this lane, or special-case short passes, and state in the plan that the floor is a contributing cause. Without this the run is also ~13x slower/costlier per inventor attempt than designed.
