# LTX Motion Levers -- the cracked recipe (2026-06-16)

## SESSION CONCLUSION (operator-reviewed) -- what to actually use
- **LOCKED conservative recipe (operator approved the look):** i2v strength **0.75**,
  fps **25**, **euler** (NEVER euler_ancestral), cfg **~2.5**, 30 steps, 832x480x105.
  Keeps the character; motion is subtle. cfg is a NO-OP between 1.8-3.2 here
  (F1/F2/F3 == L2 == L3), so 2.5 is just a safe default.
- **Two rejected failure modes (seen on review):**
  1. *Different character* -- aggressive/generic motion prompts ("a person stands up,
     full-body movement") + loosened strength make the model INVENT a new person.
  2. *Face morph / drift* -- **euler_ancestral** re-rolls the face every step. Always
     use deterministic euler for i2v.
- **cfg / sampler / strength are NOT the motion lever for character-safe work.** The
  only way to get controlled motion that preserves identity is a **per-beat, subtle,
  character-faithful motion clause generated by the writer/brief LLM** (operator's
  direction). That is the real production build (see Production wiring + the LLM phase).

## The problem
A full cfg log-sweep (1.0 -> 10.0) on the i2v path produced clips that all looked
static (framediff 0.9-1.6). **cfg and sampler are QUALITY knobs, not motion knobs** --
sweeping them could never produce motion.

## The fix -- the REAL motion levers
Motion in LTX i2v was gated by three things the cfg sweep held constant the whole time:

1. **i2v conditioning strength** (`LTXVImgToVideoConditionOnly.strength`): 0.75 -> 0.30
   = unpin the video from the still so it can move.
2. **frame_rate** (`LTXVConditioning.frame_rate`): 25 -> 10 = the model assumes more time
   elapses per frame -> larger inter-frame motion.
3. **prompt**: static description -> explicit motion verbs ("leans forward, gestures,
   turns head, stands up, dynamic full-body movement, camera push-in").

Plus a minor lever (the operator's hunch, confirmed):
4. **sampler**: euler -> euler_ancestral = ~+12% motion (ancestral injects fresh noise
   each step). Real but small next to 1-3.

## Measured (still=abtest, cfg 1.8, 30 steps, seed 1, euler unless noted, 832x480x105)
| variant | strength | fps | sampler | src | sharpness | motion |
|---------|----------|-----|---------|-----|-----------|--------|
| cfg sweep (ref) | 0.75 | 25 | euler | i2v | 111-133 | 0.9-1.6 |
| M1 | 0.30 | 10 | euler | i2v | 63 | **9.08** |
| M2 | 0.30 | 10 | euler_ancestral | i2v | 63 | **10.18** |
| M3 | -- | 16 | euler | t2v | 277 | 4.45 |

~6-10x more motion than the entire cfg sweep. Visual: M1/M2 show real motion (talking,
standing up, faces changing) but soft (strength 0.30 lets the image drift). M3 (t2v)
is crisp but uses no still anchor.

## The tradeoff
framediff measures CHANGE, not GOOD change. Low strength = more motion but softer/looser.
Likely sweet spot to dial: **strength ~0.45, fps ~16, euler_ancestral, motion prompt.**

## Production wiring (TODO -- not yet done)
Two layers (keep the frozen-mini quality path intact):

1. **Engine motion defaults (global, fixed):** euler (not ancestral), i2v strength
   ~0.6-0.75, fps ~16-25, anti-deform negative. Expose as opt-in env knobs
   (`OTR_LTX_I2V_STRENGTH`, `OTR_LTX_FRAME_RATE`, `OTR_LTX_SAMPLER`) with defaults that
   exactly preserve current output.
2. **Per-beat `motion_clause` (LLM-generated) -- THE real motion lever.** Add a field to
   the beat/brief schema, filled by the writer/brief LLM under HARD constraints:
   - allowed verbs only: talks, gestures slightly, leans, nods, glances, breathes,
     shifts, blinks;
   - banned: stands up, walks, runs, turns around, "dramatic", "full-body";
   - MUST name the actual subject from the brief (never generic "a person");
   - one short present-tense sentence.
   Append the clause to that beat's LTX positive prompt. This keeps each beat's own
   character while adding subtle, controlled life. Spec + roundtable before building.
