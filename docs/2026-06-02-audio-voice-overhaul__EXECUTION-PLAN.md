# OTR Audio + Voice-Casting Overhaul -- EXECUTION PLAN (build order)

**Branch:** `v2.0-alpha` · One file, execution-only. Build -> wire JSON -> full `tests/` -> commit, each sprint.
**Lean-alpha scope (local-first):** character voice **`indextts2`(default) > `chatterbox` > `bark`**; announcer `kokoro|chatterbox`; music **`stable_audio_3`(default, local + ComfyUI-native) > `musicgen` > `stable_audio_open`**. IndexTTS2 ships as the out-of-box default with a **non-blocking commercial-license warning** (weights need Bilibili authorization for commercial use; freely downloadable + fine for local/personal use). The registry is model-agnostic -- a new engine = one adapter + one profile row + bank entries, no graph surgery, so models drop in as we go. Commercial layer = **three-state gate** (clean / known-gated->warn / unknown->stop). No manual overrides, no SFX, no multi-mode migration framework (each re-addable later).

## Build orchestration -- waves
Dependency-ordered. SHARED-FILE steps (`__init__.py`, the workflow JSON, every full-regression + commit) are SERIAL gates, never parallel. A `--no-parallel` serial path always exists -- parallelism is an optimization, never required to ship.

**Parallel-safety rules (non-negotiable -- file authorship is NOT enough; runtime state races too):**
- Any concurrency = one **git worktree per agent**. No agent touches the shared venv: either pre-install all deps serially in R0a, or each worktree gets its own venv.
- Per-agent env: distinct `OTR_AUDIO_CACHE_DIR`, `OTR_TEST_TMP`, `COMFYUI_TEMP_DIR`; **no shared `otr_runtime.log`**; fixtures live in the agent's own test module or in Wave 0 -- **never a co-edited `conftest`**.
- An agent writes ONLY the paths on its SSOT row. Existing-file edits (0c, 1g) get their own worktree or a serial slot -- never concurrent co-edit.
- A wave's serial integration (register + full `tests/` green + commit) must pass before the next wave opens.

- **I-7 VRAM 14.5 GB.** Single-engine residency; `del`+`gc`+`empty_cache` inside `execute()`'s `finally` BEFORE return, so `audio_done` transitively implies all three engines unloaded; HF caches need explicit teardown of every object; a physical `gate_signal` edge from the post-unload assembler into the first video loader (the lock alone doesn't stop the video branch co-loading -> OOM).

- **I-11 Post-engine audio DSP runs on CPU.** Resample/pad/downmix/fade/mix run on `.cpu()` tensors (move at the engine->assembly boundary); no audio op after the forward touches CUDA, else the baseline varies under the non-strict default. ## Central contract -- `ResolvedVoiceRequest v1` (frozen in R0a/Wave 0)
Frozen dataclass; every field tagged IN_KEY or IGNORED; `cache_key=sha256(canonical_json(IN_KEY))`; same object feeds the engine.
IN_KEY: `request_schema_version, role, engine_profile_id, engine_name, engine_impl_version, char_id, line_id, occurrence, prepared_text_sha256, voice_ref_id, voice_preset, delivery_profile_id, delivery_profile_version, episode_seed, cast_lock_revision, stable_line_seed, sample_rate, channels, quantized_params(integer-tick), source_ref_sha256, commercial_clean`.

`delivery_profile_id`+version stay in the key as identity even while only `neutral` ships (removing them forces a future re-baseline). One helper `_seed_to_int64(*parts)->int` does every sha256->seed reduction; Bark chunk seed = `_seed_to_int64(stable_line_seed, chunk_index)`.
**AUDIO-batch contract (transcribe, don't redefine):** existing Bark output `{waveform: tensor[B,1,T], sample_rate:int}`; empty batch `[1,1,0]`. Assert at SceneSequencer + EpisodeAssembler ingest.
