The wiring is already largely provided by the existing driver/SL/Director generic infrastructure, but the `music_visual` role compat missing `audio_ref` will silently reject `ltx_av_music`, and the aspect-change degradation lacks a distinct failure class for the LOUD restamp.

MUST-FIX BEFORE BUILD:
1. **[role_compat.py]** `music_visual` role does not declare `audio_ref` as a required input, yet `ltx_av_music`’s `required_inputs` tuple includes `audio_ref`. The role-compat filter (used both in Director and ShotLock) will reject the engine for the `music_visual` slot, making it unselectable. Implement the planned additive touch: append `"audio_ref"` to the `MUSIC_VISUAL` required-inputs list unconditionally. Without this, `ltx_av_music` can never be wired.
2. **[retry_taxonomy + render_driver]** The plan calls for a “LOUD restamped policy” when `ltx_av_talk` degrades because of aspect change (landscape → pillarbox). The current `classify_failure` only maps OOM / DEPENDENCY_MISSING / INVALID_DAG / CRASH_BEFORE_LOAD. Add a new `FailureKind` (e.g., `ASPECT_CHANGE`) and make the engine’s `assert_usable` raise a specific exception that `classify_failure` catches and maps to it. This ensures the restamp log line contains the aspect-change reason, not a generic label, satisfying the acceptance grep.
3. **[fallback chain for ltx_av_music] (verify at build)** The plan’s fallback chain `ltx_av_music → ltx_video → still_kenburns` depends on `ltx_video` having a declared `fallback_engine` attribute in the registry (or a synthetic overlay). The grounding’s `SYNTH_FALLBACKS` only overlays `hunyuan3d_talk → humo`; no overlay for `ltx_video`. Confirm that the registered `ltx_video` engine already sets `fallback_engine = "still_kenburns"`. If it does not, the chain will terminate at `ltx_video` instead of reaching the floor, causing a `RenderFloorError` when `ltx_av_music` also fails. This is a hidden dependency.
