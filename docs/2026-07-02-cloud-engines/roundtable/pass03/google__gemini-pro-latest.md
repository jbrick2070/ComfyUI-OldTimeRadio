In the grounding (`registry.py`, line 71), `EngineUnusable.__init__` requires `(self, engine: str, role: str, reason, detail: str = "")`. Passing only the flag will throw a `TypeError` (missing positional arguments). Fix: The resolver must pass the requested engine name and role name: `EngineUnusable(engine, role, EngineUsabilityReason.GATED_BY_FLAG)`.
2. [Sec 7] `lipsync_overlay` token rejection. Sec 7 states video adapters will declare `lipsync_overlay` as a requirement. In the grounding (`role_compat.py`, line 34), `INPUT_TOKENS` is strictly limited to `{"text_prompt", "init_image", "audio_ref", "base_clip_ref"}`. Any adapter declaring `lipsync_overlay` in `required_inputs` will be permanently, silently excluded by `engine_fits_role` (line 86: `if not required_set <= INPUT_TOKENS: return False`). Fix: Map lipsync requirements to the existing `audio_ref` token, or explicitly add `lipsync_overlay` to `INPUT_TOKENS` and `ROLE_AVAILABLE_INPUTS` in `role_compat.py`.
3. [Sec 3] Budget gate sequencing deadlock. Sec 3 mandates the per-episode cost gate runs "before first media dispatch". You cannot accurately estimate the cost of video generation (which is duration-based) before the audio lane has generated the audio clips to determine their exact lengths. Fix: Run the budget gate incrementally per-dispatch (reserve before call, reconcile after), or use a worst-case text-length heuristic to reserve video budget pre-run.
4. [Sec 2] `commercial_clean` protocol violation. Sec 2 states rows carry `license_audit_status` and `commercial_clean` "derives from it". Fix: Cloud adapters must explicitly implement `commercial_clean` as a boolean property (`return self.license_audit_status == "commercial_clean"`) so duck-typing and release gates do not crash on a missing attribute.
5. [Sec 2] `resolve_default_engine_for_role` namespace blindness. The proposed helper signature is `resolve_default_engine_for_role(role, profile)`. There are three isolated registries (Audio, Video, Image), each with their own `default_engine_for_role` method. The helper lacks the context to know which registry to query. Fix: Pass the registry instance or modality string to the helper: `resolve_default_engine_for_role(registry, role, profile)`.
