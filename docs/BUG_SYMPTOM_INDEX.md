# OTR Bug Symptom Index

Symptom-first TRIAGE index. You have an error string or an observed behavior; this file
maps it to the known bug CLASS, the authoritative id(s), the root cause, the fix pattern,
and the verify. It is an INDEX, not a bug log: it clusters ~250 corpus entries by the
symptom a person actually sees or pastes, and points at the real record.

SOURCE OF TRUTH is the three files listed under Sources. NEVER edit bug content here --
this index only POINTS. To change a root/fix/verify, edit the log or the Bible, then
update the pointer here. Every id below was verified present in its source file on
2026-07-17; ids are not invented.

How to query: grep this file for your error substring or observed behavior -> land in the
matching cluster row -> open the cited id in its source file for full evidence + the
regression test. Id forms: `PBUG-YYYYMMDD-NN` lives in `PROD_BUG_LOG.md` (grep the id
directly). Bible rules are written here as `BUG-NN.NN` for readability, BUT the Bible's own
`id:` field is the BARE number -- to find one, grep `BUG_BIBLE.yaml` for `id: "11.38"` or
just `11.38`, NOT `BUG-11.38`; `BUG-LOCAL-NNN` appears there only as a `legacy_id:` back-ref.
`Lesson N` lives in `PRODUCTION_SPRINT_LESSONS.md`.

## Domain 1 -- Structured-LLM-pass failures (typed JSON contract)

The largest domain. A local/remote model must emit a strict pydantic artifact; it drifts,
and a fail-closed validator halts the lane before dialogue/media spend. Shared meta-rule
(Lessons 2, 3, 4, 14): keep the five representations in lockstep (base prompt, typed schema,
worked example, validator, repair prompt); a change to one demands an audit of the other
four. Python may repair only mechanical facts (ids, ordering, enums, offsets), never
authored prose.
