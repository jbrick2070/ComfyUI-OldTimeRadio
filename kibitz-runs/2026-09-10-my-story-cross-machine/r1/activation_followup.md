# Post-dispatch activation check

The Mac audit corrected an important causal link after R1 dispatch. This is
additional grounding evidence, not a rewritten pre-dispatch anchor.

The resident constrained-generator cache really does retain mutable LMFE
request history, and cleanup really defines local schema classes. However,
the CURRENT My Story cleanup path does not bind those schemas:
_otr_structured_call.invoke_structured_slot calls its supplied slot directly,
and the ordinary My Story creative/technical closures are unbound. Therefore
the dynamic cleanup schemas do not populate LMFE's by_schema on the reported
run. Do not claim that retention caused the observed Mac kill, or promote this
static observation as a new live-backed production failure.

The ownership correction is still relevant before adding P1 grammar binding
and for existing constrained callers. Its actual failure semantics and tests
are a separate prerequisite, not the Mac incident's established explanation.

Existing Mac teardown already calls mps.empty_cache and synchronize; final
writer unload is after both cleanup passes. My Story returns before the legacy
SDC cache closure is created. Neither a missing MPS flush nor the historical SDC
alias is an established cause here. The next Mac proof needs per-boundary
process footprint, MPS allocated/reserved memory and the final preceding log
event to distinguish transient offload duplication from retained device pools.
