### BUG-LOCAL-402: §4D procgen blend emitted `format=gbrpformat` → scopes + burned captions silently lost every render  [FIXED `99320ae` 2026-06-14]
- **Date:** 2026-06-14 | **Phase:** 5 (post-upscale procgen blend / ffmpeg) | **Bible candidate:** yes (concatenated ffmpeg filter steps need an explicit `,`/`;` separator; a step var that ALREADY ends with `,format=gbrp` + a second literal `format=gbrp` collapses into the bogus `format=gbrpformat`)
- **Symptom:** Live look-QA of a published episode showed NO burned SDH subtitles AND NO audio-reactive CRT scopes (the pillarbox side-areas stay black). Server log: `[PostUpscaleProcgenBlend] ffmpeg blend failed -- Error applying option 'gbrpformat' to filter 'format': Option not found ; falling back to source-copy so the pipeline still produces a deliverable`. The episode still publishes (obs_publish OK) but visually degraded.
- **Cause:** `nodes/otr_post_upscale_procgen_blend.py` 3-input branch (§4D scopes). When `green_only_overlay` is ON (the default), `green_only_step` ALREADY ends with `,format=gbrp`; the `[1:v]` (pgn) chain then appended ANOTHER literal `format=gbrp` with no separator → `...,format=gbrpformat=gbrp[pgn]`. ffmpeg parses `gbrpformat` as a bogus option on the `format` filter → the whole `filter_complex` is rejected → the node's try/except falls back to a plain source-copy, which carries NEITHER the scope overlay NOR the `ass=` caption burn (both live only in the failed graph). Default-on overlay = every episode degraded. Suite missed it: no test built the 3-input + green-overlay filter and checked it was well-formed.
- **Fix:** FIXED `99320ae` (2026-06-14). `pgn_gbrp = "" if green_only_step else ",format=gbrp"` so the gbrp pin is added EXACTLY once with the proper comma (green_only_step supplies it when ON; pgn_gbrp when OFF) → one `format=gbrp[pgn]`, no `gbrpformat`. Regression guard `test_build_cmd_3input_scopes_no_double_format_gbrp_bug402` asserts no `gbrpformat`, exactly 3 gbrp pins, and the caption ass-burn survives in both overlay states.
- **Verify:** full suite **4254 passed / 28 skipped**, Bug Bible 16/7/3 green @ `99320ae`. Restart ComfyUI Desktop + re-render → the final should show burned subtitles + audio-reactive scopes in the side areas.
- **Tags:** ffmpeg, filter-complex, procgen-blend, captions, scopes, source-copy-fallback

### BUG-LOCAL-401: flux_still rejected for the music slot — missing role tag, not a real incompatibility  [FIXED `9465dbd` 2026-06-14]
- **Date:** 2026-06-14 | **Phase:** 5 (video director / role-compat) | **Bible candidate:** yes (an engine's `roles` tuple must list every role its `required_inputs` actually allow, or the full-registry per-slot dropdown offers a pick that fail-closes at execute)
- **Symptom:** GUI Run (after BUG-400 fixed, the pipeline now reaches video) → `OTR_VideoDirector` (node 87): `ValueError: engine 'flux_still' does not fit any role for slot 'music_video_model' ('music_visual',) ... Pick a compatible model -- no silent swap.` Operator set all three video slots to flux_still (fastest path); announcer + other_beats validated, music did not.
- **Cause:** `flux_still` (`nodes/_otr_video_engines/cheap_families.py`) declared `roles = (announcer_visual, scene_broll, character_video)` — missing `music_visual` (and `background_abstract`). `engine_fits_role` requires the role to be in the engine's `roles` AND `required_inputs ⊆ role's available inputs`. flux_still needs only `text_prompt`, which `music_visual` DOES supply — so there was NO real input incompatibility, just a missing role tag. The director lists the full registry per slot (V-6) and fail-closes an incompatible pick at execute, so the missing tag surfaced as a hard stop. Suite missed it: the check only fires for registry-known engines on the live box (different in OTR_TEST_MODE).
- **Fix:** FIXED `9465dbd` (2026-06-14). Expanded `flux_still.roles` to all five roles (`announcer_visual, music_visual, character_video, scene_broll, background_abstract`) — a plain still is the fast universal pick and is valid wherever only `text_prompt` is needed (every role). No dropdown filtering (operator wants flux_still selectable everywhere) and no workflow-JSON change (shipped JSON uses ltx_video/humo_1.7B; the operator's flux_still picks now validate). Regression guard `test_flux_still_fits_all_roles_bug401`.
- **Verify:** full suite **4253 passed / 28 skipped**, Bug Bible 16/7/3 green @ `9465dbd`. Restart ComfyUI Desktop to load, then Run with flux_still in any slot → OTR_VideoDirector validates.
- **Tags:** role-compat, video-director, engine-roles, fail-closed, comfyui

### BUG-LOCAL-400: Enabled cloud writer slots block the whole graph — sentinel `(enable …)` not in COMBO list  [FIXED `d967c6b` 2026-06-14]
- **Date:** 2026-06-14 | **Phase:** 0 (script writer / INPUT_TYPES) | **Bible candidate:** yes (ComfyUI COMBO contract: a saved widget value must be a member of the INPUT_TYPES list — state-dependent dynamic dropdowns must keep the saved/“off” value valid in every state)
- **Symptom:** GUI **Run** → node 1 `OTR_LedgerScriptWriter` turns red, run produces nothing. Server log:
  ```
  Failed to validate prompt for output 12:
  * OTR_LedgerScriptWriter 1:
    - Value not in list: comfy_slot_a_model: '(enable Comfy Credits)' not in (list of length 21)
    - Value not in list: openrouter_slot_a_model: '(enable OpenRouter)' not in (list of length 344)
    - Value not in list: openrouter_slot_b_model: '(enable OpenRouter)' not in (list of length 344)
    - Value not in list: comfy_slot_b_model: '(enable Comfy Credits)' not in (list of length 21)
  Output will be ignored        # also outputs 92, 93, 85, 94, 7 → whole episode aborts
  ```
- **Cause:** `openrouter_catalog_dropdown_choices()` / `comfy_catalog_dropdown_choices()` (`nodes/_otr_model_catalog.py`) include the enable-sentinel **only when the lane is DISABLED**; when **ENABLED** they return the catalog (344 OpenRouter / 21 Comfy) with **no sentinel**. The saved workflow `workflows/otr_scifi_16gb_full.json` (widgets_values[19–22]) stores the sentinel as each slot's value. With `OPENROUTER_API_KEY`+`OTR_ENABLE_OPENROUTER=1` and `OTR_ENABLE_COMFY_CREDITS=1` set, `openrouter_enabled()`/`comfy_credits_enabled()` return True → sentinel dropped from the lists → ComfyUI's pre-exec COMBO validator rejects the saved sentinel → all node-1 outputs ignored. The S3 resolver `_clean_slot_value()` ALREADY treats a parenthesized sentinel as “unset” (→ local/env fallback), so **only the validation layer is wrong**, not the resolver. Suite stays green because the slot-widget tests exercise the disabled (sentinel-only) branch; nothing loads the real JSON through COMBO validation with the lanes enabled.
- **Fix:** FIXED `d967c6b` (2026-06-14). New `_lead_with_sentinel()` helper in `nodes/_otr_model_catalog.py`; both `openrouter_catalog_dropdown_choices()` and `comfy_catalog_dropdown_choices()` now lead EVERY branch (disabled, enabled+cache, enabled+empty, import-fail) with the enable-sentinel, so it is always `choices[0]` — the slot's valid 'off' value AND its INPUT_TYPES default. This keeps 'off' the default even when a lane is enabled (no silent default to a billable model). No workflow-JSON change (the stored sentinel was already correct). This is the SYMMETRIC fix to the 2026-06-10 sentinel restore (`test_workflow_json_guardrails` L694-700), which only covered lanes-OFF and left lanes-ON broken. The S3 resolver `_clean_slot_value()` already maps the sentinel to 'unset → local/env fallback', so no resolver change was needed. **Workarounds (no longer needed):** pick a real slug per slot, OR unset `OTR_ENABLE_OPENROUTER` / `OTR_ENABLE_COMFY_CREDITS`.
- **Verify:** DONE — full suite **4252 passed / 28 skipped** (4249 baseline + 3 new guards), Bug Bible **16 / 7 / 3**, all green @ `d967c6b`. New guards: `test_enable_sentinel_leads_when_enabled_bug400` (openrouter + comfy) + `test_saved_slot_sentinels_validate_with_lanes_enabled_bug400` (INPUT_TYPES end-to-end with both lanes ON). **Operator action to see it live:** the running ComfyUI loaded the old module at boot (14:21) — **restart ComfyUI Desktop**, then re-Run with lanes enabled; node 1 should validate and outputs should no longer be ignored. Sibling audit: only the cloud slot pickers had the state-dependent omission; `creative_writing_model`/`technical_model` are curated-always-listed (the live log showed only the 4 cloud slots failing), so no other dropdown is affected.
- **Tags:** comfyui-combo, input-types, json-wiring, openrouter, comfy-credits, validation, dynamic-dropdown
