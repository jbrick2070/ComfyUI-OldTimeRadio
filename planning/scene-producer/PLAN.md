# OTR Scene Producer - go-forward plan

Baseline `main` 93eb468f, ComfyUI core 0.42.1, frontend 1.55.18, comfy-sdk 0.5.0, comfy-api-proxy 0.1.6, 2026-10-22. Since release 2.3.37 Radio Play Studio ships inside the pack, so Studio changes reach registry users too. Every seam below was read in the real files; re-read them at the commit you start from. The approved page design is `mockup.html` in this folder; its simulated state handlers are illustrative, and the state rules below govern implementation. Implementation and live proof are outstanding. Existing uncommitted work in `nodes/_otr_shared/cast_text.py`, `nodes/_otr_story_brief_helpers.py` and `nodes/otr_meta_brief_image_prompt.py` must land under its own owner before a chunk edits those files; chunk 3 cannot overwrite it.

## What it is

An optional shot editor for Radio Play Studio, built and proven first on the My Story bank. The first producer run writes, voices and paints the episode exactly as today, then stops before video. The user sees one card per shot (about one per spoken line), grouped by scene, each with its still. They paint again, edit or keep a few cards or none, film, then publish. Only what changed is re-rendered. Audio, cast, voices and timing never move on a visual edit. A partial result never publishes. ComfyUI runs everything; Studio edits and submits. With the one new widget blank, every workflow, bank and Studio form behaves exactly as today, in the same node order.

## Graph contract

**One widget, in ComfyUI's advanced mode.** Shot Lock gains one optional input, its only widget, appended last:

```python
"direction_json": ("STRING", {"default": "", "multiline": True, "advanced": True,
                              "tooltip": "Written by Radio Play Studio's shot editor. Leave empty."}),
```

- **`advanced: True`** is ComfyUI's flag for a power-user input. Frontend 1.55.18 hides it behind the node's advanced toggle and lists it under Advanced inputs in the side panel. It is visibility only: the widget still saves its value, so positions in `widgets_values` never shift.
- **Not `socketless`.** The frontend creates no input entry for a socketless widget. That breaks the repo's rule that every widget value has an input descriptor (`tests/test_canonical_widget_input_parity.py`), and the server does not enforce it anyway. The Workflow Validator's literal-only check is the guard instead.
- **Off the app form.** `config/app_mode.json` lists its rows by name, and this one is not added.
- **No node modes.** Every node stays at Always; no mute or bypass is used, so a saved graph never changes shape.
- **Saved graphs.** Canonical serializes `[""]` plus one input descriptor; every generated workflow regenerates. Old `[]` graphs already convert on all three converters. The writer gains nothing: Studio sets its existing `replay_from`.

**No pruning, no new output nodes.** Studio submits the whole shipped graph. Core runs output nodes first, so turning Shot Lock or the dispatcher into one would reorder ordinary runs; neither changes. A stage ends where its last node, after freezing, returns `ExecutionBlocker(None)` on every output.

| Stage | Run | Ends at |
|---|---|---|
| Stills, first | Fresh My Story run, as today | Dispatcher #91: freeze, block |
| Stills, again | Replay of the latest bundle, no LLM | Dispatcher #91: freeze, block |
| Video | Replay of the latest bundle | Batch #92: freeze, block |
| Publish | Replay of the latest Video bundle | Mux #85, unchanged; no freeze |

**Direction JSON**, versioned: `project_id`, a unique `attempt_id` for every submitted run including Publish, `stage`, `out` (the bundle this run writes), `source` (previous bundle's manifest digest; absent on the first run), scene notes keyed by scene id, per-card picture text and motion text keyed by shot id, take numbers per character, still and clip, and kept ids separated into `kept.stills` and `kept.clips`. No selection in V1: each stage acts on everything changed. Takes are sent in full on every run; Studio's project file is their source of truth. Before the first submit, define the exact version-1 schema in the shared module and matching Studio tests; reject unknown ids and motion edits on cards without an editable action.

**The direction lives only on the wire.** Shot Lock puts the parsed direction, stage included, on the ledger it passes downstream as one runtime key. With the widget blank it adds no key at all, and removes one inherited from a bundle. Node 89, the dispatcher and Batch read it from their wire input. The durable save and the freeze strip it. A blank-widget replay of a producer bundle therefore reaches the mux.

**Blank means byte-identical.** Every new write, hash and refusal is keyed on that runtime key. With the widget blank, Shot Lock adds nothing, the dispatcher stores no payload and keeps today's rows, Batch computes no reuse key, node 89 does not rebuild, and the resolver answers "not producer" without refusing anything. No shared index or helper changes behaviour unconditionally.

**Validation is in the Workflow Validator.** `VALIDATE_INPUTS` cannot refuse a prompt: core drops only the outputs that depend on the failing node and still runs the writer. Node 63 makes one new call in `validate()`, after the mux-gap check and before the `validate_anyway` branch. That puts it ahead of both `_queue_time_readiness_gates` calls, which roll lanes, preflight clouds and fetch assets, and leaves those two calls exactly as tests pin them. A blank or missing direction passes with no checks. Otherwise node 63 refuses a linked or non-literal direction and checks:

- **Shape:** the version, and `out` matching `^\d{2}-(stills|video)$`, which also keeps it clear of the clip store.
- **Stage rules:** every Stills and Video run needs an `out` that does not exist yet; Publish has none. The first Stills run has no `source` and a blank `replay_from`; every later run needs both.
- **Bundle:** `load_replay_manifest` hashes every member, and `source` must equal the manifest digest, the sha256 of `manifest.json`.
- **Engines:** from chunk 3, the per-role image engines must equal the ones the Stills freeze stamped into the manifest, resolved by both directors' own code in the order they run: node 87's picks, then node 88's fallback, its own map for a still-unresolved custom pick, and its role check. Stamp and check land together, with the repaint on replay that an engine change would corrupt.
- **Ids:** every replay's direction may name only the cards, scenes and cast its bundle's `cards.json` shows, and only edits each card can take: no picture text, still take or Keep on a card with no still, and no action on a card with none to edit. Anything else would do nothing at all, and an edit that does nothing looks like a broken one.
- **Unpainted edits:** from chunk 3, compare each object's effective still-input digest against the bundle's `cards.json`, after applying Keep. It covers picture text, scene note, character identity/take, still take, resolved image engine and preserved prompt payload. Any mismatch refuses Video or Publish, so scene and cast edits cannot bypass painting. Motion-only edits do not change this digest. Keep retains verified bytes; it never exempts a missing or tampered asset from validation. The digest a card shows is the one the dispatcher stamped on its still's row when it painted it (`producer_input_hash`); a kept row carries the digest of the paint it keeps, so a card un-kept after a bulk edit is caught, since its pixels predate the edit. A card whose still failed has no stamped digest; its baseline is the texts and takes it was last asked to paint, so an edit made to retry it is caught too. The digest uses the still object's own character, which an announcer beat's still does not have, so each cast member's take is also compared directly with the take its pictures were painted with: a character with no still of their own still shows it in their portrait.

A raise there halts the prompt before any asset loads. Execution is sequential, so a duplicate queued behind its twin fails at node 63 once the first has frozen `out`.

**One shared module.** `nodes/_otr_producer_direction.py` owns direction parsing and validation, `bundle_path(project_id, out)` confined with `confine_to_output_tree`, the manifest digest, and the `cards.json` reader and writer. Node 63, Shot Lock, the dispatcher, Batch and the freezer all use it, and each re-validates names, because `/prompt` is unauthenticated. Studio cannot import the pack, so it mirrors the `cards.json` schema and checks its version.

## Stages

**Stills.** The first Stills run's dispatcher stores the image prompt payload it received, before its own merge, as `images.producer_prompt_payload`, and every later Stills run keeps that same payload. It must be added inside the dispatcher's own rebuild of the images section, which replaces the whole section with six named keys. On replay the image prompt node rebuilds from that payload. Raw per-card `picture_text` and scene `note` remain separate authorities: the ledger keeps them as `images.producer_raw_texts` (first run: each card's text from the first payload, no notes; later runs: the previous bundle's, with the direction's texts and notes put in their place, an explicit empty note clearing one), and `cards.json` shows them. Compose their effective text exactly once per run and replace the object's prompt completely. Never append a new note to the previously composed payload; replacing or clearing a note must remove its old contribution. Only a beat's own scene still (`still_<beat>`) takes its card's text; a blank picture text is refused. Identity, co-references and every other field are kept, and no template or LLM runs. Only the Stills stage paints. There the dispatcher runs its cached path instead of verify-only and mints only misses, portraits first. In Video and Publish it keeps today's verify-only replay path and paints nothing. Takes are never written onto shot rows, because `ShotRow` forbids extra fields.

**Motion is the action, not the finished clip prompt.** Initialize the Motion box from `creative["motion"]`. Shot Lock applies an edited action in its replay branch after the engine override and before the durable planned stamp. For that edited card only, it deterministically recomposes `creative["text_prompt"]` and its prompt hash from frozen appearance, setting, expression, the new action, camera and dialogue only where the existing lane policy permits it. Extract the pure composition already used by `derive_creative_directives`; do not call an LLM or re-author unrelated leaves. Unchanged actions do not recompose. The render driver's existing lane composers and finishers still own framing, sound, dialogue policy, required openers, style and final receipts. Changing `text_prompt` alone is insufficient: LTX and HuMo compose again from the structured leaves. An edited action also clears the director's `sound` leaf, written for the old moment: on the lanes that decode audio from the prompt it would otherwise win over the lexicon, which then derives the sounds from the new action. Cards without an editable `creative.motion`, including Ghost's separate finalized prompt path, show no Motion box, and forged motion edits on them are refused.

Take numbers above zero enter every seed branch: bookend, fixed mode, scene character and portrait. A character's take enters the identity seed of every scene still of that character, whether or not the lane mints a portrait. Studio's My Story graphs mint none without photos: scene stills take their identity from a hashed identity prompt. Take 0 is today's seed exactly. Kept objects retain their verified row through bulk scene or character edits. Keep on a card accepts its current still and clip separately. A picture edit or Paint again clears both keeps; a Motion edit or Film again clears only the clip keep and preserves any still keep, including its prior effective prompt/digest under deferred scene/cast changes. In producer mode the dispatcher keeps one row per object, the newest replacing the old, so the render driver's first-row-wins portrait index needs no change; the replaced rows move to `images.producer_superseded`, which the cache-hit lookup also reads, so an undone edit is a cache hit on the still it restores. Paint again raises the still's take and invalidates its clip; Film again raises only the clip's take and keeps the still. Motion-only edits invalidate only the clip and can go straight to Video. Node 12 renames the workspace on every run; Shot Lock already adopts the renamed id and rebases every path before the dispatcher, which prefers that wired id, so minting on replay writes into the right folder with no change.

**Video.** Each shot's reuse record lives in `video.producer_clip_reuse[shot_id]`, a map beside the shot rows, never on them, because `ShotRow` forbids extra fields. Paths are episode-relative. Shot Lock's replay branch re-stamps the imported video section, so the map survives; Batch writes it in producer mode when it stamps its video section. A record holds the clip as the render returned it -- receipts, segments and foley fields included, from which the manifest row is rebuilt -- and the attempts, with size and hash of every stored file. Built in chunk 4a: `nodes/_otr_producer_clips.py` holds the key, the store and one run's reuse; the render driver keys a shot once its requests are built (`_reuse_filmed_clip`) and commits it once whole (`_producer_commit`). The map holds exactly the shots the run delivered; a floored shot has no record and is filmed again.

The lookup key has its own version and hashes the prebuilt causal segment requests, with external image/audio paths replaced by file hashes, plus the coverage/join plan, initial still, resolved seeds, recipe id, engine id/version, the episode's render policy (device and precision), the settings the render driver applies outside the request (the fear cape and the foley join duck), every `OTR_` setting in the environment an engine may read at render time (`causal_env`: all of them but those the pack writes while a prompt runs, credentials, and settings that only say where files live, how long to wait, how many calls run at once or what a call is expected to cost), and the model files an engine declares (`model_artifacts`: name, size, mtime). The clip take enters through the seed. Runtime workspace paths, run ids and observability do not enter it. A setting outside the `OTR_` names, or a model file an engine does not declare, is not seen: swapping either under the same engine id and version calls for a new project. A CHAIN successor's image does not exist until its predecessor renders: represent that dependency by predecessor segment identity and chain policy, not by a generated terminal-frame hash. Actual terminal-frame hashes stay in the completed evidence. Resolve the same causal key in a fresh replay workspace before any engine preparation or cloud call. Verify the clip, foley and all required retained segment assets on use, hashing their bytes every time; a record keeps files, never paths, and a foley receipt must name the stem the record lists. A hit rehydrates Batch's clips and receipts, so render engines, the manifest, credits and foley rebuild exactly as if rendered: the VRAM peak is the one measured when the clip was filmed, and each receipt carries `reused_from`, so the run's trace never claims a render it did not do. A miss re-renders the whole shot. The clip take re-derives the seed. `_RECEIPT_CAUSAL_KEYS` is untouched, so old bundles still verify.

**Clips survive a crash.** Batch currently receives `run_real_episode` only after the whole episode, so saving there cannot protect individual completed clips. Add a producer-only completion callback inside the render driver, called after a whole shot has completed and its clip, receipts, segments and foley are assembled, on both the serial path and each cloud worker's completion. Producer deliverables go directly to the active episode's `clips/` and `audio/foley/`, never solely to swept scratch. The callback commits that shot into the per-project store, `_replay/p/<project>/clips/<key>/`, before reporting its durable completion. Blank runs install no callback and keep today's behavior.

Store writes use a unique sibling staging directory, copy and hash every required asset, write the record last, then atomically rename to `<key>/`. A valid committed entry is immutable; concurrent identical writers verify and reuse it. Lookup ignores partial staging entries and refuses corrupt/incomplete records rather than accepting directory existence as success. It checks the bundle's map first, then the store, and copies a hit into the active workspace. A run that dies at shot 80 of 100 keeps the 79 committed clips, and the next run films only the rest. The Video freeze includes every clip/foley asset and record it uses, so every bundle stays self-contained without the store.

**Floors are failed cards.** A shot whose still or clip floored, to the scene still or to black, gets no successful reuse record and no successful cache row, and `cards.json` marks it failed. Its separate `video.producer_floor_payloads[shot_id]` carries the existing sanctioned-floor manifest payload, reason and hashes of the assets it actually uses. Freeze and replay preserve that payload, so an explicitly kept floor can be rehydrated during Publish without rendering; it stays visibly degraded and is never passed off as a successful clip. Publish refuses while any failed card is not kept. Keep accepts only that verified floor and does not waive source/audio/asset integrity checks.

Built in chunk 4b: a floored shot, and a refused-still gap, gets a payload of its floor marks and, when one was drawn, its floor clip; `cards.json` shows `clip`, `clip_take`, `clip_input_hash`, `still_state`, `clip_state` (filmed, kept, failed) and `clip_floor` (why), and the combined `state` puts failed before kept before filmed. A kept clip is the bundle's record used whatever its key; a kept floor comes back with its marks, so it stays degraded; Keep never vouches for a file that does not verify. A clip take is mixed into the request seed itself, because `_seed_from_hash` reads the request hash alone whenever there is one.

On an explicit retry, clear the retried shot's old `cloud_floor`, `content_floor`, `budget_floor`, `floor_render` and attempt status before rendering, and replace its prior floor payload with the new outcome. (Built: every shot that renders sheds those marks -- `render_driver._rendered_shot` -- including on an ordinary replay of a floored episode, which used to report a re-rendered beat as floored.) A successful still retry replaces its required-scene-target receipt too. A successful clip retry becomes filmed and reusable; copying old floor markers onto a successful result would leave it falsely failed forever. Unretried kept floors retain their original reason and payload.

**Publish.** Batch, in the publish stage, raises before any engine if a shot lacks a verified reusable clip or a kept floor. Otherwise it rehydrates every shot, and composite, captions, credits and mux run as today. No generation weights load. Built in chunk 4c: node 63 refuses a Publish whose cards show a shot not filmed as it stands -- no clip, a floor or refused-still gap not kept, or an action or clip take changed since it was filmed (`unfilmed_shots`); the render, in publish mode, raises at the first shot it finds no clip for (`ProducerClips.find`) or a gap whose card is not kept (`check_gap`), before any weights load. A still repainted after the last Video run is not visible in `cards.json`, so only the render's key check catches it. With every part of a direction built, `not_yet_supported` and its two call sites are gone.

**Freezer.** It moves to `nodes/_otr_replay_freezer.py` with relative imports, and `derive_engine_bundle` moves with it.

- **Errors:** it raises `ReplayBundleError`, never `SystemExit`, which would kill ComfyUI's prompt worker. The seven test assertions that expect `SystemExit` change with it.
- **No git:** it takes the source commit as an argument. Only the `scripts/` wrapper calls git, because a `subprocess` call under `nodes/` is a registry-scan finding. A producer caller passes a known build revision or `unknown` when unavailable; it never claims a package version is a commit.
- **Signature:** the node helper's `freeze(ep_dir, out_root, *, allow_no_plan)` keeps its shape and gains keyword-only `dest=`, `source_commit=` and `include_render_outputs=False`. Only producer callers pass the new destination/output options. The script keeps a thin public `freeze` adapter that supplies `_git_commit()` to the helper even when another script imports it; its CLI delegates through that adapter. It re-exports `find_master` and `derive_engine_bundle` without moving git under `nodes/`.
- **Members:** clips and `audio/foley` are frozen only with `include_render_outputs=True`. Video always passes it; a later Stills freeze also passes it when retained clip-reuse or kept-floor payloads reference render outputs, and includes every referenced asset. Thus Video -> Stills -> Video stays self-contained even when the clip store is unavailable. The ordinary CLI leaves it false and adds no render-output members.
- **Engines and cards:** only a producer freeze stamps the resolved per-role image engines and includes `cards.json`, for node 63's checks and Studio. An ordinary CLI freeze adds neither producer fields nor producer members.

Bundles live at `otr/episodes/_replay/p/<project>/<nn>-<stage>`, short for Windows path limits. Nothing is deleted automatically in V1: each stage run adds one bundle and one workspace, and the operator removes old ones by hand.

**Readiness.** One resolver (`producer_replay_needs`), called by node 63's three readiness gates: `_otr_visual_assets` and the two cloud preflights. It finds Shot Lock by class type in the queued prompt, since the gate-in walker never reaches it. Only when a direction is present does it refuse a graph with more than one. A project's first run is an ordinary live run to every gate. A Stills replay needs the image engines its bundle's stills were actually painted with, a Video replay its frozen plan's lanes (never the live dropdowns), Publish none, and no replay needs writer assets. Both lists are stamped by every producer freeze in the manifest's producer section (`image_engines_used` from the dispatcher's per-role histogram, `video_engines` from the shots), and node 63's admission has verified that manifest before any gate runs. `_otr_visual_assets` loads standalone by file path, and the balance preflight's top-level imports are pinned, so each imports the resolver lazily and falls back to today's replay behaviour where it cannot load.

**Known costs, accepted for V1.**

- **CRT base video.** Node 12 renders and renames it on every stage, at a measured 53 frames a second, which is a few minutes for a typical episode.
- **Double hashing.** Node 63 hashes every bundle member, and the import hashes them all again.

## Studio

The approved design is `mockup.html`.

- **Entry.** A quiet second button, "Direct the shots first", sits beside "Make the episode" on the My Story path. The form stays first and folds to one line once a project exists; the board takes the run section.
- **Runs.** Every run submits the shipped graph through the existing busy guard. The first takes the user's My Story choices, and the project records which workflow it used: the reference twin when photos were given. Later runs reuse that recorded workflow and the first run's recorded form choices, because `runner.workflow_for` picks the twin only when the bank is my_story and the image engines come from the video director's widgets. Node 63 refuses a replay whose image engines differ from the bundle's. They set `replay_from` to the previous bundle, Source to `roll (any eligible bank)`, and `source_ref` and every My Story box to empty, which the writer's replay check allows. A small internal patcher writes those values and `direction_json` by node type; the form's `apply_choices` rejects unknown fields and stays unchanged.
- **Routes.** Studio's own server gains project read, draft save and stage start operations. Reads and atomic draft saves remain available while rendering; only stage start uses the shared GPU busy guard. Restore unresolved producer attempts into that guard before accepting ordinary or producer submissions after startup. ComfyUI gains no routes.
- **Results.** A succeeded job ends a stage once its verified result is saved locally. Only Publish picks the mux output; `runner.stream` today always does, and would raise `EpisodeMissing` on every other stage. Studio's server reads `cards.json` and media from the bundle through ComfyUI's `/view`. Keep the verified bundle-relative JSON intact, copy media to `out_dir/projects/<project_id>/media/<sha>.<ext>`, and derive a page view whose media URLs are `/episodes/projects/<project_id>/media/<sha>.<ext>`. Never ask the page to resolve bundle paths against sha filenames. The page never calls ComfyUI, and a deleted bundle never blanks it. Every successful stage emits the existing `done` event with its stage and project; only Publish includes the final-video fields. `Run.add` therefore releases the busy guard, and the page branches on stage before reading video fields. Failures use `error`; no new terminal event type is needed.
- **`cards.json`.** The freeze writes this small versioned view, the one contract between nodes and page:

  ```json
  {"version": 1, "project_id": "", "attempt_id": "", "stage": "", "bundle": "", "source": null,
   "cast":   [{"char_id": "", "name": "", "picture": "", "take": 0}],
   "scenes": [{"scene_id": "", "note": "",
               "shots": [{"shot_id": "", "char_id": "", "line": "", "start_s": 0.0, "dur_s": 0.0,
                          "picture_text": "", "motion_text": "", "still": "", "clip": null,
                          "still_take": 0, "clip_take": 0, "still_input_hash": "",
                          "still_dirty": false, "clip_dirty": false, "state": ""}]}]}
  ```

  Media fields are bundle-relative paths. `state` is one of painted, filmed, changed, failed or kept; still and clip dirtiness are separate. Chunk 3 also writes, per card, what node 63 needs to recompute the digest without the ledger -- `payload_hash`, `still_char_id`, `engine_id` -- and `motion_editable` / `picture_editable`, so the page shows a box only where an edit can land; the manifest's producer section records the direction's `kept` lists. The project derives its live draft state against this immutable rendered view. `motion_text` is the editable action leaf, never the full composed prompt. An empty action is a valid explicit edit on an editable card; do not silently restore the old value.
- **Page.**
  - **Cast:** one picture per character with Paint again; it repaints that character's shots unless kept. The picture is the portrait when the lane mints one, otherwise the character's first scene still.
  - **Scenes:** collapsed, opening when one holds a changed or failed card.
  - **Card row:** thumb, who, the spoken line, Picture and Motion text, Paint again, Film again, Keep. Picture/scene/character changes invalidate affected unkept stills and their clips; Motion edits invalidate clips only. Paint again repaints the still; Film again keeps the still and films a new take. Picture edits/rerolls clear both artifact keeps, while Motion/Film again clears only clip Keep. The page derives dirty/failed reasons per artifact instead of treating one pressed Keep toggle as a waiver. These rules replace the mockup's shared textarea dirty handler.
  - **Buttons:** Paint the stills (N changed), Film the shots (N to film), Publish the episode, each with a one-line reason when disabled.
- **Progress.** In producer mode the dispatcher drives one node-level bar over its items, with `QuietInnerBars` so the sampler bars do not fight it. Batch keeps its existing frame-weighted bar. Studio preserves raw node identity, step and total for the stage bar instead of replacing them with its calibrated episode fraction. V1 does not infer an active card from timeline durations or the k-th item: video weights include coverage overhead and stills include portraits. Show a stage-level bar unless the event explicitly identifies the object.
- **Project file.** One atomic file holds the editable draft/revision, the bundle names in order and one pending attempt. Before submit, persist its unique `attempt_id`, stage, start time, source, intended `out` if any, exact submitted direction/graph and draft revision; save the returned `job.id` immediately. Submission and completion never overwrite edits made after that submitted revision. Finish a run by updating the rendered baseline and reapplying the current draft to it; a successful stage can still leave newer edits dirty.
- **Restart and uncertain submission.** Reattach known jobs with `client.jobs.get`. If a response was lost before the id was saved, a small injectable server-side JSON GET helper inspects ComfyUI's existing `/queue` and `/history` and matches the literal direction's `project_id` and `attempt_id`. Exactly one match supplies the id; multiple matches or an unavailable/ambiguous result remain pending and busy while reconciliation retries. A single empty snapshot never authorizes resubmission. Do not treat an idempotency key as a replay handle: SDK 0.5.0 rejects duplicate keys, and the proxy can accept upstream before recording its local job list.
- **Stage completion.** Stills/Video adopt only a complete verified intended bundle whose project/attempt/source match, then finish local media copying; a complete bundle can recover a result even if job history expired. Publish creates no `out` or `cards.json`: reconcile its job and retrieve the mux output from its recorded graph, then finish the local download. Retrying a failed media copy never reruns generation or Publish. An explicit terminal failure with no complete bundle permits a new attempt; incomplete output is never treated as done, and unresolved acceptance keeps the pending record.
- **Languages.** New strings go into every language file (the parity test enforces it).
- **README.** The README gains a Producer section only after the proof passes. When it mentions the feature relative to contest judging is the operator's call.

## Not in V1

| Cut | What you give up |
|---|---|
| A separate Prepare stage | Cards before the first stills; an edited card costs one extra still |

## Implementation traps

- `ExecutionBlocker` is imported lazily from core, never redefined, and stubbed in tests. It is always given `None`; a message turns the skip into an execution error.
- Shot Lock's `IS_CHANGED(**kwargs)` stays as is; a test calls it with no arguments.
- The saved prompt payload is node 89's output as the dispatcher received it; the dispatcher's own merge raises on a duplicate id.
- The runtime key is top-level on the wire ledger, never inside `video` or `images`, which Shot Lock and the dispatcher stamp. A test asserts a producer run leaves no such key in the durable ledger.
- Producer mode travels in `led`. The one argument `dispatch()` adds to its `dispatch_images` call is the stage bar's quiet (chunk 2c, `quiet_inner_bars`): a resource `dispatch()` must own so its `finally` can close it, passed only on a producer run and `None` on every other. The test stand-ins that replace `dispatch_images` accept it as an optional keyword. The dispatcher's 3-tuple, Batch's `{"ui", "result"}` 2-tuple and Shot Lock's 5-tuple all keep their shapes.
- The descriptor appended to node 90 is `{"name": "direction_json", "type": "STRING", "shape": 7, "widget": {"name": "direction_json"}, "link": null}`, after `gate_in`, so link 284 keeps `dst_slot` 3. Old graphs send no key and new ones send `""`; both are blank.
- `tests/test_visual_asset_validator_stdlib.py` executes only `INPUT_TYPES`, `IS_CHANGED` and `validate` from the validator's source, so any new helper `validate()` calls must be reachable from that seam, or the test is updated in the same commit.
- Restart ComfyUI and Studio after chunk 1. Servers started before it refuse the new graphs as a widget-count mismatch.
- The freeze reads the post-rename workspace; node 12 renames before Shot Lock runs.
- Every bundle is frozen before the mux ever runs, so its master is the assembler's, never the foley mix, and Publish always replays a Video bundle.
- An edited My Story still records its source receipt as `stale_source_receipt`, the dispatcher's existing label for a changed prompt. Nothing gates on it; it is the truthful record of a user edit.

## Proof

- **Blank widget:** on the 5080, node order, VRAM peak, the durable ledger and the published file match a baseline. Old `[]` vectors, the app form and mux discovery are unchanged. A blank-widget replay of a producer bundle publishes. The freezer CLI produces the same bundle for an ordinary episode as before.
- **Zero supplied images on My Story:** Stills, Video and Publish produce a playable final in `otr/obs/`. Master, cast and timing hashes equal bundle 1's. Only the first run calls an LLM. With photos supplied, the reference twin works the same way.
- **One card edit:** exactly that still and that clip re-render; the reports show the rest reused.
- **Paint again:** gives a different image, and take 0 is byte-identical to today. A character's Paint again in the cast strip repaints only that character's unkept shots.
- **Film again:** reuses the still and re-renders the clip.
- **Motion only:** changes the effective final request and re-renders only the clip, preserving the still, lane framing, sound and audio policy. Unsupported cards have no Motion control and refuse forged edits.
- **Video, then Stills again, then Video:** re-renders only the changed shots, with foley intact.
- **Duplicates and bad input:** node 63 refuses each of these before any model loads:
  - a duplicate queued behind its twin;
  - a tampered bundle;
  - a linked direction;
  - a missing still or changed audio;
  - a changed image engine;
  - a Video run that still carries unpainted edits.
- **Crash mid-Video:** after local and cloud completions, the next Video run reuses every atomically committed shot, ignores partial store entries and films only the rest. CHAIN keys stay equal across fresh workspaces.
- **Floors:** a floored shot shows Failed and blocks Publish until it is filmed again or kept. Successful retry clears the old failure and creates a reusable result; keeping it publishes the verified degraded floor with no engine call.
- **Publish:** with a shot missing, it refuses before any engine. Complete, it publishes and loads no generation weights.
- **Studio restart:** a running job re-attaches; a lost submit response reconciles without duplicate work; Stills/Video recover complete bundles; Publish recovers its mux download without a new bundle. Draft edits made during a run survive completion and restart. Both ordinary and producer submission stay busy until an uncertain attempt is reconciled.
- **Widget:** `direction_json` is hidden behind Shot Lock's advanced toggle, absent from the app form, and its value survives a save and reload on the canvas.
- **Registry zip:** `planning/` stays out of it.
