# Qwen-Image 2.1 probe on the 5080 (2026-11-22)

A MEASUREMENT, not a qualification. No engine adapter was written or registered, and no
canonical-workflow leg was run. The scout had this model on WATCH since 2026-10-26 with
"fit and licence not checked"; this note is what checking found.

## What was run

- Box: RTX 5080 Laptop 16 GB, ComfyUI core 0.46.2 (already ships `TextEncodeQwenImage21` and
  `QwenImage21Cache`; no core update needed). Headless server from the soak launcher.
- Files (ungated Comfy-Org repack, `Comfy-Org/Qwen-Image-2.1`), all sha256-verified against the
  hashes Hugging Face publishes, now in `C:\ComfyUI-Models`:
  - `diffusion_models/qwen_image_2.1_int8_convrot.safetensors` 7.26 GB (cb74113c...)
  - `text_encoders/qwen3vl_8b_int8_convrot.safetensors` 9.35 GB (8bfd0f6e...)
  - `vae/qwen_image_2.1_vae_bf16.safetensors` 0.68 GB (bb21f747...)
- Graphs follow the official ComfyUI templates (t2i, image edit, background removal): 25 steps,
  cfg 1, euler / simple, resolution 1024. The Klein arm follows the shipped engine recipe
  (16 steps, cfg 1, euler / simple, ModelSamplingFlux shift ln(16), ReferenceLatent at height 768).
- Outputs and contact sheets: `output/otr/_probe_qwen_image_21/`. Harness and raw numbers were
  kept in the session scratchpad only.
- Licence: Hugging Face metadata says `qwen-research` (not Apache). The licence text itself was
  not read. Per the standing ruling, licence is not a gate.

## Reading

- New capability for OTR: native transparent stills. The compositor
  (`nodes/otr_silent_composite.py`) already has a straight-alpha RGBA foreground path, fed today
  only by 3D character frames. Whether the image dispatcher keeps the alpha channel end to end is
  UNKNOWN and was not tested.
- Face hold: no clear win over `flux3_klein_ref`. Qwen costs about 2.5x the time per edit and
  needs the 9.35 GB encoder. Only worth adopting for the transparency.
- Not done: no engine registered, no canonical leg, one seed per face cell, no numeric identity
  score, licence text unread.

## What was decided and done (same day)

The operator asked for the engine to be "an image model [that] can fulfil announcer, character or
music slot", so it was registered as an opt-in PEER among the still engines (commit 546dddddd),
text-to-image only, `commercial_clean = False` (Qwen Research License), not as a transparency
special. Edit mode and native transparency are not wired.

**Live proof, 2026-11-22:** the canonical runner on `workflows/otr_canonical.json` with the
`otr_16gb_still` row and its three image picks switched to `qwen_image_21` in the dropdowns,
1 act. RESULT SUCCESS in 12 min 55 s, 15 stills minted by the engine at 1472x832, no
out-of-memory, published to `otr/obs` as
`needle_fold_20261122_221816__sbke__stmo__qwi2__koko__news__cg412__sa3_final.mp4`
(1920x1080 H.264 + AAC, 227.6 s). The three recurring characters stayed recognizable across
their beats from text-to-image alone.

**Not covered by that proof:** the weights were already on disk, so the pack's own first-use
download was NOT run for this engine; alpha through the dispatcher (the engine returns plain
RGB); 8 GB, Mac and AMD.

**Open follow-ups, each its own decision:** a reference-image row (the model's edit canvas
follows its first image, which does not match how the dispatcher hands over a portrait), native
transparent stills into the compositor's RGBA foreground path, and a first-use fetch proof.
