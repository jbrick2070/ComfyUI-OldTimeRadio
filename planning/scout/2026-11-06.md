### TurboH3-FL2VA-I2VA (TurboDiffusion) -- WATCH
- https://huggingface.co/TurboDiffusion/TurboH3-FL2VA-I2VA (card read; updated 2026-11-04).
- What: 4-update DMD distillation of MiniMax H3 FL2VA for image-to-video with synced audio (steps=5, i2va). Challenges the H3 fl2va lane on step count (author-stated schedule; no speed figure read).
- Sweet-spot build: none for ComfyUI. Offers bf16 (61.7 GiB) and a W8A8 file of 20.4 GiB in TurboDiffusion's own format (not int8_convrot, not a core loader format).
- 16 GB fit: 20.4 GiB W8A8 does not fit 16 GB without offload (estimate). Not for 8 GB.
- ComfyUI: no. Needs the TurboDiffusion H3 code and SpargeAttn. Licence: MiniMax H3 Community License (territorial limits listed on the card). Ungated.
- Risk: not a ComfyUI path; author says W8A8 can change results and evaluation was five 768p cases. Related distillation LoRAs (DMAD, HyperFlow, Pika Turbo) are already in SEEN and load through core.
Other: Viggle-Remake (H3 video-to-video edit LoRA, card read in part, needs the 144 GB H3 base; recast and object edit, not a beat generator) -- SKIP. ## Upscalers
### RelayVSR (Comfy-Org repack; core support, master-only) -- TEST
- https://huggingface.co/Comfy-Org/RelayVSR (card read; created 2026-11-05). Origin: https://huggingface.co/kopper/RelayVSR (4x), https://huggingface.co/lightx2v/RelayVSR_X2 (2x, card read). Already in SEEN as WATCH on 2026-11-04; material change: native core support and a Comfy-Org repack now exist.
- What: video super-resolution that the X2 card says suppresses temporal flicker in generated video. Would add a post pass for the LTX lanes: a 832x480 render becomes 1664x960 at 2x. Could be a route for 8 GB lanes to a 16 GB-class picture if it fits (not shown).
- Sweet-spot build: YES, Comfy-Org: diffusion_models/relayvsr_x2_lightx2v_int8_convrot.safetensors 5.16 GB and relayvsr_x4_int8_convrot.safetensors 5.16 GB; vae/relayvsr_flash_vae_x2_fp32.safetensors and x4 each 0.13 GB. Ungated, Apache-2.0.
- 16 GB fit: no ComfyUI VRAM figure read. Estimate: 5.2 GB weights plus activations; clip length and tiling decide it. 8 GB unknown.
- Speed (measured by the lightx2v authors, H100 80 GB, LightX2V runtime, 1024x768 input, 243 frames): 5.35 s for 2x (45 FPS); 4x original 19.3 s. A 5080 Laptop figure does not exist.
- ComfyUI: core commit 2f894332 "Support RelayVSR" (2026-11-05, adds a model_vsr loader and nodes in nodes_wan.py) is on master only; `git tag --contains` is empty, v0.44.1 lacks it. Registry pack ComfyUI-FL-RelayVSR (4x, created 2026-11-06, flagged in listing) is an alternative. It is not the spandrel UpscaleModelLoader path: it needs its own core nodes.
- Risk: master-only; the box runs tagged releases, so the probe waits for the next tag or a master checkout. Quality versus the LTX refine pass is unmeasured.
- Proposed test: run the X2 file on one 832x480 LTX 2.5 clip and compare with the 16 GB refine output by eye; record peak VRAM.
Other: Registry "upscale": Auto-TensorRT-Upscaler (image, TensorRT, flagged) and riverfield-comfy-nodes (chunked video upscaler, flagged), both packs only, not read. The Pruna upscale template is the partner node Pruna P-Video Upscale (CLOUD, in core v0.44.0 per the docs changelog); not local. The same changelog lists no RelayVSR entry for v0.44.0 (dated 2026-11-04), which agrees with RelayVSR being master-only. RelayVSR ComfyUI-FL pack above. MambaIR, Tessera, X2 Detail VAE already in SEEN.
