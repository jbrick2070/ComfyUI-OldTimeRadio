## Voice / TTS
### Higgs TTS 3 (Boson AI) -- WATCH
- https://huggingface.co/bosonai/higgs-tts-3-4b (card read in part; first-seen by us today, the repo itself dates from about June 2026, so it is older than the 72-hour window; reported because it covers all eight OTR languages and is not in SEEN).
- What: ~4B autoregressive TTS, 24 kHz, zero-shot voice cloning, 100+ languages, inline tags for emotion, prosody (speed, pitch, pauses) and sound effects. Card lists en, es, fr, it, pt, ja, zh and hi all in the "WER/CER under 5" tier. Would challenge Kokoro for cloning and character voices; it is nowhere near Kokoro's 0.19x CPU real time.
- Sweet-spot build: none. model.safetensors is 9.3 GB (bf16). Community 4-bit builds exist (Reza2kn AWQ / NVFP4 / MLX / ONNX, cloud19 fp8, onnx-community) but no int8 or int8_convrot; names seen only in a search listing, not read.
- 16 GB fit: no published VRAM figure read. My estimate: 9.3 GB of weights plus codec and cache fits 16 GB; 8 GB only with a 4-bit build (unmeasured).
- ComfyUI: no core support (no Higgs TTS loader found in the ComfyUI tree; the only "higgs" hits are the unrelated Higgsfield partner nodes). Would need a custom pack; none checked.
- Speed: the card gives accuracy tables (WER/CER, authors' own); no real-time factor read.
- Licence: Boson Higgs TTS 3 Research and Non-Commercial licence, with a Creator Use Grant (monetised content allowed with credit "Boson AI's Higgs Audio"); production or embedding in a product needs a separate licence. Not a gate here, but a pack that ships it would be embedding.
- Risk: no ComfyUI path, size, speed unknown. Test to propose when a loader exists: clone two character voices in es and ja, compare against current voices by ear.
Other: the registry TTS search shows comfyui-audio8tts (Audio8, already in SEEN) and comfyui-paxa (already SKIP). Web search found no TTS model dated November 2026. Ming not reported (parked).

## Video
### H3 Continuity Studio (KadoBOT/ComfyUI-H3-Continuity-Studio) -- WATCH (news page only)
- https://github.com/KadoBOT/ComfyUI-H3-Continuity-Studio (read only the comfyui-wiki write-up dated 2026-11-03; the pack README was not fetched, so WATCH at most).
- What: node pack that builds a film from a list of MiniMax H3 clips; keeps identity across cuts by feeding a five-frame window of earlier footage (from the saved clip's latent) back into H3 as <Video N> references, with "Cast" mode (each character as they look now) and optional OpenAI-compatible story writer. Relevant to the face-changes-between-beats concern. Author states the renderer is not visually benchmarked across all memory modes.
- Sweet-spot build: not applicable (pack only; H3 int8_convrot repacks already tracked). Needs a ComfyUI build with the core H3 Context Windows node, and H3 weights (does not fit 8 GB).
- Risk: unproven, pack only. Related packs seen in the registry (minimaxh3-director, comfyui-h3md-director, h3zerostudio, comfyui-feihou-easy-h3, seriesmith) were not read.
Other: core v0.44.0 adds no video model (Pika H3 Flex nodes are cloud). Searched HF text-to-video, image-to-video, video-to-video: only items already in SEEN or H3 community LoRAs. ## Image
### Mage-Flow and Mage-Flow-Edit (Microsoft) via Comfy-Org repack -- WATCH
- https://huggingface.co/Comfy-Org/Mage-Flow (repack card and file list read) and https://github.com/microsoft/Mage (README read: it names variants and one speed figure only). Released 2026-07-22 per comfyui-wiki, so it is older than 72 hours; it is new to SEEN and has a sweet-spot build.
- What: 4B native-resolution text-to-image (30-step Base, 30-step RL-aligned, 4-step Turbo) plus an instruction-edit family with the same three variants, Qwen3-VL-4B text encoder. Edit variants could challenge flux3_klein on the 8 GB lane for plain edits. The README says nothing about identity preservation or how many reference images the edit model takes, so it is not shown to challenge flux3_klein_ref.
- Sweet-spot build: YES, ungated, Comfy-Org. diffusion_models/mage_flow_edit_int8_convrot.safetensors 4.16 GB, mage_flow_edit_turbo_int8_convrot.safetensors 4.16 GB, mage_flow_int8_convrot.safetensors 4.16 GB, mage_flow_turbo_int8_convrot.safetensors 4.16 GB (https://huggingface.co/Comfy-Org/Mage-Flow/tree/main/diffusion_models). bf16 files are 8.23 GB. Text encoder qwen3vl_4b_bf16 8.88 GB (no int8 text encoder in this repo), VAE 345 MB.
- 16 GB fit: authors' figure (comfyui-wiki, from release materials, A100, bf16): peak about 18-20 GB at 1024x1024. With int8_convrot the diffusion file is 4.2 GB, so my estimate is it fits 16 GB comfortably; 8 GB plausible with the 8.9 GB text encoder offloaded (estimate, unmeasured).
- ComfyUI: core, no custom pack. comfy/ldm/mage_flow is in the ComfyUI tree and is in tag v0.44.0 (git tag --contains; this clone is shallow so an earlier tag may also carry it). Comfy-Org templates image_mage_flow_edit_int8 and image_mage_flow_edit_turbo_int8 exist (names only, JSON not read).
- Speed (authors, A100): Turbo 0.59 s per 1024 image, Edit-Turbo 1.02 s per edit. Not measured by us.
- Licence: MIT (README model table; edit variants not listed separately). One commentary article claims Microsoft discourages product use; unverified.
- Risk: no identity-hold claim; quality claims are the authors' own. Test to propose: Edit-Turbo int8_convrot, one character portrait, three outfit and pose edits, compare face hold with flux3_klein_ref by eye.
### BluePixel-Turbo (vivo) -- WATCH
- https://huggingface.co/openvivo/BluePixel-Turbo (card read; updated 2026-11-03, intermediate checkpoint per the card).
- What: FLUX.2-klein-9B based instruction editor with a DCAE-F64 autoencoder: native 4K edits in 4 steps (authors: 8.7 s per 4K edit on a Kunlunxin XPU, not CUDA). Would sit beside flux3_klein_ref as an editor, though the card does not claim multi-reference identity.
- Sweet-spot build: none from the authors (transformer 36.3 GB fp32, 10 shards). The news page names a community INT8 repack, t8star/BluePixel-Comfy, about 28 GB (not read on the Hub, and not int8_convrot).
- 16 GB fit: no; the 9B transformer alone is 36 GB in fp32 and 28 GB int8 (estimate: needs heavy offload). 8 GB: no.
- ComfyUI: no core support; official path is a Diffusers pipeline, community pack T8mars/Comfyui-BluePixel-T8 (news page).
- Licence: FLUX non-commercial. Risk: size, no core loader, authors say further training is planned.
Other: HF text-to-image and image-to-image by trending: everything else is in SEEN or is Qwen-Image-2.1 / Krea 2 / MOSS-Image variants covered earlier. MOSS-Image-heal (fp16-safe MOSS-Image retrain, news page only) noted, not rated. Anima RGBA not relevant.

## Writer LLMs (experimental)
### rwkv7-147m-early-modern-english (geoppls) -- WATCH
- https://huggingface.co/geoppls/rwkv7-147m-early-modern-english (card read in part; updated 2026-05-31).
- Base/params: RWKV-7 from scratch, 147.4M, context 1,024 tokens, bf16, single model.pth (295 MB, RWKV format, not safetensors, no GGUF seen). Apache-2.0.
- Corpus: Text Creation Partnership, 60,172 documents 1473-1800 (EEBO, ECCO, Evans), about 1.97B tokens, original spelling (loue, vp, hath, wee). Checkpoint chosen as the purest before later Gutenberg training. No sample sentence read.
- Fit: trivial (295 MB). Runs through the RWKV runtime, not transformers/llama.cpp as far as I read.
- Experiment: a base-style generator for Early Modern English fragments, e.g. prologue or proclamation text to seed a Shakespeare-lane scene. It is tiny and not instruction-tuned, so it cannot write a play on its own.
Other found, not rated: DebadityaMalakar/ArchaicLLM-v0 (Qwen3-4B-Instruct fine-tune, card has no corpus information, so no uniqueness shown). Talkie, TimeCapsuleLLM, GPT-1900, MonadGPT are already in SEEN.
