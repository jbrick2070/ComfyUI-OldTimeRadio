## Voice / TTS
### VintageVoice (AutomatedJanitor/vintage-voice) -- TEST (new to SEEN)
- https://huggingface.co/AutomatedJanitor/vintage-voice (card read; GitHub README https://github.com/Scottcjn/vintage-voice also read). HF repo last updated 2026-06-17, 37 downloads, so it is not a 72-hour item; it surfaced through the old-time-radio search and is new to us.
- What: fine-tune of F5-TTS (F5TTS_v1_Base, 337M) on about 164.6 h of public-domain pre-1955 audio (Prelinger, Old Time Radio, FDR library, LibriVox, Library of Congress; 44,345 segments). It applies transatlantic / newsreel / radio-drama delivery to ANY reference voice via cloning; it does not make a specific historical speaker. Would sit beside Kokoro as an optional cloning engine with period delivery.
- Weights: model.safetensors 1.35 GB (fp32 by size; estimate), vocab.txt; ungated. Licence CC-BY-NC-4.0 (inherited from F5-TTS); code MIT.
- Sweet-spot build: none. At 337M it needs none for 16 GB or 8 GB (estimate: well under 2 GB VRAM).
- Languages: English validated; card tags en, fr and has Cajun French samples, but README says Cajun French output is not done. Not one of OTR's eight languages beyond en. Speed: no RTF published.
- ComfyUI: no core support. F5-TTS node packs exist on the registry (comfyui-f5-tts 1.0.27, TTS Audio Suite 5.10.5 -- latest version flagged status per API); whether they load a custom checkpoint with the v1 architecture is unverified.
- Risk: v0.1.0 experimental, about 24% of training segments have sparse or mislabeled transcripts, only the transatlantic preset is validated, demos are 5 s clips. Sample quality not heard by me.
- Test: clone two shipped character voices with the transatlantic reference and A/B against Kokoro by ear.

## Video
### Pika H3 Flex (Pika-Labs/Pika-H3-Flex) -- TEST
- https://huggingface.co/Pika-Labs/Pika-H3-Flex (file list and card read; HF updated 2026-10-29; Comfy walkthrough https://comfyui-wiki.com/en/news/2026-10-29-pika-h3-flex). Templates added in Comfy-Org/workflow_templates commit 6cd9cff (10-29): video_pika_h3_flex_t2v / fl2va / ref2va (per the wiki; names not confirmed from the repo).
- What: two LoRAs on MiniMax H3 (fl2va and ref2va), distilled to 6 sampling steps from a 50-step teacher, CFG 1.0, LCM sampler with fixed sigmas, loaded with stock LoraLoaderModelOnly. ref2va takes up to 9 images, 3 videos, 3 audio clips (character reference, motion transfer). Challenges the H3 fl2va and ref2va lanes on speed.
- Files: comfy/loras/pika_h3_flex_fl2va_comfy_bf16.safetensors and ..._ref2va_comfy_bf16.safetensors, 1.96 GB each (bf16), fp32 originals 2.77 GB. Ungated; MiniMax H3 community licence.
- Sweet-spot build: base side YES (Comfy-Org/MiniMax-H3 pruned int8_convrot 20.97 GB, already used by shipped lanes). The LoRA itself: bf16 only; no int8 LoRA found. The article says its templates pair a pruned int8 H3 with the adapter.
- 16 GB fit: no VRAM number published. Wiki figures (Pika / testers, not measured by me): 5 s 1344x768 about a minute on one card; 6-step 1440p in 3 min 17 s. Fit equals the existing pruned int8 H3 lanes plus a 2 GB LoRA (estimate).
- ComfyUI: no new model code (LoRA loader); needs the H3 support already in tagged core (H3 lanes ship). Core master commit 6651247a adds H3 context windows (master-only, no tag).
- Risk: Pika states no end-to-end Comfy render was verified; do not stack other turbo LoRAs; the 6-step quality against the shipped step count has not been checked, so this is an A/B for face and lip-sync, not a swap.

## Writer LLMs (experimental)
### GPT-1900 / GPT-1905 family (mhla) -- WATCH (new to SEEN)
- https://huggingface.co/mhla/gpt1900-instruct-v3-sft and https://huggingface.co/mhla/gpt1905-d34 (cards read; repos dated Feb-Apr 2026; chat site https://gpt1900.com/ says hosting moved to HF).
- Base: nanochat custom GPT trained from scratch, 3.29B params, 34 layers, 2048 context, 32k vocab. Corpus: pre-1900 books, newspapers, letters (22B tokens); the 1905 sibling trained on about 40B tokens of pre-1905 text. Cutoff 1900 / 1905. Instruct variant tuned on 53,458 synthetic multi-turn chats. Licence MIT.
- Formats: raw PyTorch .pt only (instruct v3: 10.6 GB, fp32); no safetensors, no GGUF. 16 GB fit: 3.29B in bf16 is about 6.6 GB (estimate). Runs only through the nanochat code, not transformers or llama.cpp.
- Sample sentence: none on the cards (prompt example "The luminiferous aether").
- Experiment: pick the 1900/1905 base (not the physics RL variants) and have it continue a Victorian-style cold open; the point is period knowledge baked in (it has never heard of relativity), not prose quality. Needs a small nanochat wrapper, hence WATCH.
