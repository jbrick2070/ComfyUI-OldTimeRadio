## 1. Ming-3.0-TTS (inclusionAI Ming-3.0-tts-tiny, Comfy-Org repack) -- TEST
- Link: https://huggingface.co/Comfy-Org/Ming-3.0-TTS (original https://huggingface.co/inclusionAI/Ming-3.0-tts-tiny). Repack updated 2026-10-26.
- What: 7.9B-total / ~1.3B-active MoE speech model (model card figures). Zero-shot cloning, voice design from a text description, emotion/speed/pitch control, non-speech tags, multi-speaker dialogue. Languages per card: zh, en, de, es, fr, ko, ja. No it, pt or hi.
- OTR lane: voice. Sits beside Kokoro; helps cast consistency and es/fr/ja/zh episodes.
- 16 GB fit: repack file is 9.07 GB (int8 "convrot", measured file size). Runtime VRAM not published; estimate 10-12 GB, so it would run alone in its own phase. 8 GB: unlikely (estimate).
- ComfyUI requirement: CHANGED since the partial report. I read origin/master: comfy_extras/nodes_ming.py only holds TextEncodeMingImageEdit (Ming-Image). There is NO Ming TTS loader in core, tagged or master. A community pack exists: https://github.com/Saganaki22/ComfyUI-Ming-3-tts (nodes "Ming TTS Load Model" / "Ming TTS Generate", supports 0.5B and Tiny; only Tiny does native multi-speaker). I did not inspect its code or whether it reads the Comfy-Org int8 file.
- Weights: ungated, MIT, int8 only in the repack.
- Risk: third-party node pack; int8 kernel behaviour on Blackwell unknown; delivery on period radio unknown; no it/pt/hi.
- Verdict: TEST (probe through the custom pack; check the pack's own deps first).
